# VibeNovel v3 — 本地 AI 小说工作台

当前版本 **3.0.0a12 / Studio alpha**：独立的本地 Web 小说工作台。按创作过程分组导航，支持从零构思、初版总纲候选、卷章规划、资料中心与方法提炼、参考书归档与逐章研究、研究方法入库与本书调用、写前上下文包、本地审稿、固定样章、历史检索、已有小说修订、多模型候选协作、作者盲评、文稿版本比较恢复、改编审批和持久任务。CLI 核心仍支持 Python **3.9+**、标准库离线运行。

生成统一使用 **API**，通过「模型与角色」管理模型、密钥、角色和预算；未迁移用户也可使用旧「模型与 API 设置」。Codex交互接力已移除；旧任务只保留历史。创作规划提供卷章结构、人物表与规划关系图、伏笔和计划时间线；可选本地BGE语义检索已提供。人物等资料按条编辑、实际定稿事件图谱、Tiptap富文本/行内批注、多文件原子定稿、DOCX/PDF和桌面封装尚未实现。

完整操作见 [Studio 使用手册](docs/studio_user_guide.md)，网页顶部也有「使用手册」入口。下列括号中的版本表示能力引入阶段，操作按当前版本说明；阶段实施计划和审计中的旧验收记录保留当时状态，不代表当前功能仍未实现。本轮交互问题及验证范围见 [交互审计](docs/studio_interaction_audit_v3.md)。

## 从大纲继续创作的入口

从「创意与定位」选用总纲后，点击页面上方「创建规划包」；已有大纲直接进「故事设计 → 大纲与卷章」。没有包时创建表单自动展开，选择来源、起始章节和本批1–10章后，点击「预览规划包」，再确认付费生成。已有包时用「新建规划包」展开表单，规划包下拉框只查看已有结果。人物、世界、时间线、伏笔和写作风格是同一个包的不同视图；整包审批应用后，还要逐章提取并审批章计划才能起草。

规划表单内「为本次任务选择资料与方法」可勾选本书卡片、已固定用于本书的个人资料，也可「从参考书检索选段」：选择已有索引、检索、勾选、预览精确文字，再「将所选片段加入当前任务」。检索弹窗保留规划表单；缺索引或授权可去资料中心处理，专用往返流程在当前页面会话内保留规划输入，刷新/关闭页面不保证保留这份未保存表单。选材不等于采用方法或放宽外发权限，改选后须重新预览。

只写参考书名不会自动读取本机收藏。任务预览中的「本次资料与方法」是实际补充文本核对，不是选材器；「返回选择本次资料」可回表单改选。「未发送」项没有进入补充文字；方法卡已纳入也不代表其关联研究原文已发送。自动策略仍可补充材料，只用明确勾选项时先保存手动政策，最终以预览清单为准。

## 参考书研究工作台（3.0.0a12）

「资料中心」新增「精读与结构图」「语义检索」「方法效果评阅」「研究预算」。精读按顺序保存检查点和当时的角色/读者知情，展示因果、人物、线索、情绪节奏四图；主动补读与跨书比较均保留实际区间和精确证据。研究方法可先保存到个人库，作者核对、编辑、采用后再用于本书。

语义检索使用预先准备的本地中文 BGE，结合中文词项与有证据的图关系，覆盖原文、结构、表达和已采用方法。检索不收费；勾选结果、预览后点击「用于本书下一次任务」，只为当前作品固定选用，在发送前再核对版本与外发权限。规划现场也可在检索弹窗内加入当前任务。索引失效后需重新构建，不把旧向量当作来源权威。

参考书架单书可进入「目录与版本整理」，预览精确修订、拆分/合并/排序/隔离方案后发布派生版并回查父子版本映射。原件和旧版保留。研究预算独立于创作作品，精读、比较和效果试验共用上限；未知费用保留额度，中断和失败请求不会自动重放。效果试验比较三种参考条件，匿名 AI 评阅与作者评价分别保存，不自动采用方法或写入正式正文。

「精读与结构图」提供到书架授权和研究预算的直接入口；研究预算页可前往配置模型与密钥，切换研究模型后须重新填价，不沿用旧模型报价。研究/效果试验刷新会同时核对当前详情，草案、图编辑、响应修复和作者评价有未保存保护；运行中的研究应先暂停，再编辑候选图。研究响应修复只验证已保存候选，不重发付费请求。

设计、验收与真实试点范围见 [a12 实施审计](docs/reference_research_a12_audit.md)、[目录整理](docs/reference_edition_curation_v3.md)、[混合检索](docs/reference_retrieval_v3.md)、[效果评测合同](docs/reference_evaluation_contract_v3.md)。

## 启动 Studio

首次在项目根目录执行（前端构建需要 Node.js 22.12+，推荐 24）：

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -e ".[studio,test]"
cd studio
npm ci
npm run build
cd ..
.venv/Scripts/python.exe tools/studio.py
```

打开 [本地 Studio](http://127.0.0.1:8000)。后续只需最后一条启动命令；已安装入口也可使用 `vibenovel-studio --workspace <作品工作目录> --port 8000`。默认读取当前目录下 `novels/`，不自动创建示例作品、不迁移 v2。源码版默认读取 `studio/dist`；在其他位置部署时用 `--frontend <dist绝对路径>`。发行 wheel 不内置前端资源。

新建作品可选「从零构思」「已有大纲」「已有正文」三种起点。从零构思先生成并选用总纲，再展开规划；已有大纲可直接导入/粘贴；已有正文可直接创建独立修订副本。进入逐章创作后，仍须批准有效章计划才能起草；正式章节经作者审阅、批准并应用后导出。故事记忆可逐文件提案更新；**章节与多份记忆暂不构成一个原子定稿事务**。草稿和导入材料不会自动成为正式事实。

编辑器保存 Markdown 原文，阅读视图清洗 HTML；保存、恢复和生成都绑定已读版本，旧写入返回冲突并保留当前输入。正式正文和记忆只读，修改或恢复须创建提案。正式内容变化后，旧提案需重新基于当前文件提交。版本历史暂限每作品 64 MiB，编辑文件 2 MiB；普通资料原件默认 10 MiB，大部头参考小说可使用下述独立参考书架。

已保存状态和任务都在本地。关闭网页不会停止后端任务；停止后端会中断正在请求的任务，重启后需要明确重试，不自动重复付费调用。排队任务可以暂停/继续，运行任务暂停后转为中断。已返回但尚未发布的候选提供“恢复已生成候选”，不会再次调用模型。

任务页会解释已知的通用重试阻断条件，包括已存在可恢复候选、工作流节点、来源需重新选择，以及原预算组调用数/Token/金额不足。普通重试继续使用冻结的原预算，不因修改当前模型策略而清零；确需独立新任务时，先核对原记录和不确定费用，再回对应入口重新预览并明确启动。

Studio API 的socket等待超时为180秒，并非严格总耗时上限。取消立即阻止结果发布；已发出的网络请求可能继续占用工作槽直到返回或超时，不自动重复付费调用。

## 从参考书研究到创作方法（3.0.0a11）

在「资料中心 → 参考书架 → 逐章研究」打开成功节点的完整分析，或展开最终归并，点击「整理方法候选」。选择希望继续核对的方法，先预览步骤、局限和原文依据，再保存为个人方法候选。此操作只复用已保存的研究，不再次调用模型，不自动采用；节点没有方法时会明确显示，不凭书名补造。

保存后可直接进入「个人资料库 → 方法」，修改适用情境、步骤、边界和作者摘要，按固定书籍版本回查原文。研究出处只读保留，编辑后需重新采用。作者明确采用并设置外发方式后，选择「用于本书」固定版本，再按本书任务选材政策使用；手动/仅推荐模式不会自动把方法发送给模型，有界自动仍受用途、数量和字符预算限制。

方法携带原件、解析版本、研究节点/结果指纹和授权依赖。来源撤回、授权收紧后恢复、原件或研究结果被修改，都会阻止旧方法采用、绑定或任务发送；可保留原内容，将失效卡归档、撤回或收紧为仅本地。研究引文是核对依据，不自动算作后续模型已读原句，也不自动成为小说事实。当前不支持把这类研究卡再次送入旧来源提炼接口；要补读或提炼，明确选择新的原文范围。详见[桥接设计与验收](docs/reference_method_bridge_v3.md)。

## 参考书架与逐章研究（3.0.0a10）

进入「辅助工具 → 资料中心 → 参考书架」，可导入本机 EPUB、TXT、MD。参考书与正在创作的小说分别保存；原始文件归档后建立保留出处的卷章目录、UTF-8技术分册、异常记录和本地词项检索。支持目录与原文分页、原文指纹核验、重复候选和编码/控制字符核对。单原件最多128 MiB，规范文本每版本最多128 MiB，技术分册目标5 MiB、硬上限8 MiB；2 GiB是语料导入配额，包含原件、派生文本和定位等现有书库文件，不是单本或分册上限，也不是批次分析存储的总量保证。普通a9来源的10 MiB合同不变。

1. 导入后先检查目录、附记、重复候选和编码缺口。原书卷与技术分册分别显示；解析成功不能证明版本无缺章。编码缺口及NUL等控制字符保留原字节和定位，相关章段标记待核；“选本页完整正文”不会选入待核章段；选择全书仍包含全部章段，后端拒绝其中未经核对的异常范围。
2. 默认`local`，保存、阅读与本地检索不调用模型。需要研究时，在「核对与外发」明确允许所选章节外发，再到「逐章研究」选择全书或具体章段、**真实计费作品**、研究问题、输出上限和整批美元预算。计费作品提供模型策略与账本，不因此读取它的正文。模型须配置输入/输出价格；先预览实际范围、模型、调用总数、Token和总费用上界。
3. 「2. 预览范围、模型与总预算」「3. 保存研究批次」「4. 开始研究（付费）」始终可见，缺条件时就地解释。保存仅创建`prepared`批次，明确点击开始才发送API请求。超长章按段落拆节点，独立分析结构、表达、线索与方法候选，再以每组最多4个前置节点逐层归并。各层保留原文证据并可回查；这属于候选研究，不表示完成连续通读、全书理解或角色知情地图。节点和结果分页读取，预览超出前50个的节点可保存后继续核对，尚未启动。
4. 暂停会在当前请求完成并落账后阻止后续节点；关闭网页不停止后端记录。重启不重放未知或已失败的付费请求，成功候选与费用保留；必要时另选明确范围预览新批次，不能靠重试抹去不明费用。完成覆盖按章内所有分段成功计数，与解析覆盖、文学解释正确及实际使用效果分别看待。

参考书私库位于`library/books/`，批次、原件、分册、定位和分析结果均需完整备份，默认不进入Git；只复制章节文本不足以恢复引用与预算状态。a10当时仅交付语料和独立章段研究；当前a12已提供四层混合检索、连续精读候选图和跨书比较，a11已接通方法采用及本书装配。它们不保证完成整部出版作品的阅读或文学理解，也不会自动替换样章、修改正式正文/记忆或启动训练。详见[全书利用设计](docs/reference_novel_analysis_design_v3.md)与[存储合同](docs/storage_contract_v3.md)。

## 资料中心与创作方法（3.0.0a9）

左栏「辅助工具 → 资料中心」提供文献、素材、技法、风格、术语、方法六类卡片，以及来源原件、专题和研究问题。未打开作品也能整理个人库；本书资料架只包含本书资源与作者明确选入的个人库固定版本。资料、来源与方法的采用均不修改正式正文、记忆或章计划。

1. 「导入资料」收录MD/TXT，或「新建卡片」手工整理。来源默认只在本地使用；查看原文、书目信息和精确选区后，按需要允许发送作者摘要或所选摘录。导入和保存不会调用模型。
2. 在来源详情中选择片段、提炼用途和明确的计费作品，点击「预览资料分析」核对模型、范围与共享预算，然后开始分析。分析完成后，可继续预览并提炼方法；两个阶段共用原预算组。只处理选定范围，不凭书名补写未读内容。
3. 方法先是候选。核对原句、用途、步骤、输入输出、局限及反例，修改保存后点击「采用」。编辑已采用卡片会取消原采用状态；需要重新核对。引用校验只证明原句存在，不证明方法有文学效果。
4. 「本书选用」固定个人资料版本；新版由作者显式更新。「任务选材」保存手动、仅推荐或有界自动策略，可限制类型、用途、专题、必选/排除项和字符预算。推荐不会自动入模。当前网页的规划表单支持显式勾选卡片/固定资料与参考书检索片段，手动模式也能使用；其余入口可用资料中心的固定检索选择或已授权自动政策。政策中的必选不会在手动/推荐模式单独触发装配，自动模式只在已授权范围内取材，且可与明确选择共存。任务提交前显示实际补充文本与遗漏，配置或资料权限变化须重新预览。

a9阶段吸收book-to-skill的两阶段分析与按需组织、Cangjie的方法卡与出处边界机制，由Studio原生API实现；没有安装或运行上游宿主技能。普通资料卡搜索仍为有界中文词项/精确匹配；当前a12另提供参考书原文、研究结构、表达、已采用方法的四层混合检索和三条件方法效果试验，见上文。PDF/DOCX/OCR仍未实现；单次效果试验不构成文学效果认证。

个人库位于工作区 `library/`，本书库位于 `novels/<novel_id>/library/`，均默认不进入Git。请将库目录连同作品与本机配置单独备份；本书选用依赖原个人库，复制单本作品还不能自动打包个人来源。详见[设计与本轮范围](docs/knowledge_library_design_v3.md)、[方法吸收方案](docs/studio_skill_absorption_design_v3.md)及[存储合同](docs/storage_contract_v3.md)。

## 从零构思到第一版总纲（3.0.0a8）

1. 顶部点击「＋ 创建新作品」打开“开始新故事”，选择「从零构思」。书名可暂定，文件夹标识默认自动生成；选择实际需要的创作规则，未覆盖题材可用「通用创作」。已有作品直接从左栏「故事设计 → 创意与定位」进入。
2. 填写「你的故事想法」，一句话或几段粗略情节均可。这是生成时唯一必填的创作内容。阅读分类、主题/角色/情节标签、主角、叙述视角、外挂、开局、篇幅和文风均可稍后补；标签支持自定义、包含/避免与未定。阅读和内容区域的同名词表标签共享一个选择。
3. 点击「保存构思」。未配置模型也能保存半成品；保存、打开页面、切换标签和读取最新版本均不会调用模型。明确没有外挂与尚未决定分别保存；作者硬条件与可协商偏好分开。
4. 点击「预览生成」，核对当前保存版本的要求，以及规划角色的主模型、允许备用、最大技术尝试数、Token和费用预算。缺配置时从「模型与预算」打开设置，补齐API、密钥与角色绑定后返回。确认后点击「生成初版总纲」；这是一个规划节点，技术备用也占用预算，不自动启动其他角色或数百章的生成。
5. 在「总纲候选与下一步」选择结果阅读，可打开编辑器修改并保留历史。点击「选用这版继续规划」，再点击页面上方「创建规划包」。更改简报、候选或其历史版本后，旧选用可能失效，须重新核对。明确重新生成需要再次预览；相同提交键只返回同一任务，网络结果不明时先核对任务记录，后端重启不重放已受理请求。

简报保存在作品 `outlines/source/creative-brief.json`，选用状态保存在受管的 `reviews/creation-selection.json`；两者有版本历史，应随作品一同备份。总纲产物位于独立 `outlines/proposals/story-outline-<任务ID>.md`，不会覆盖旧稿、正式正文或记忆。选用只是指定后续规划依据，不能代替章计划批准或正式定稿；模型是否在语义上遵守作者条件，仍需阅读核对。

左栏按「故事设计」「写作校订」「作者决定」「辅助工具」分组；人物与世界、时间线与伏笔、写作风格直接打开同一规划包的相应视图，计划资料与正式记忆继续分开。a7页面源码、构建和截图备份仍保留，见[页面基线记录](docs/studio_ui_baseline_a7.md)。本阶段C1/C2范围及后续C3设计见[从零开书设计](docs/author_creation_workflow_design_v3.md)。

## 从大纲生成卷纲、章纲与设定

进入「大纲与卷章」的「创建规划包 · 导入或选择大纲」表单，选择该作品已导入的大纲或独立候选大纲，指定本批起始章和章数（1–10，默认3章），明确选择补充资料后「预览规划包」→「确认并生成规划包（付费）」；从构思页选用总纲继续时会带入该来源。规划包同时整理全书/卷概要、这段章计划、人物、关系、伏笔、未来事件、世界/题材设定、文风与待确认项。优先提取原稿已有内容，区分「原稿陈述」「推断」「新增建议」；原稿陈述须绑定来源版本、原文行与摘录。不要求一次生成长篇所有细纲。

查看并修改候选后，提交整包提案到审批中心，批准并应用。随后在有效的已批准包中选择一章，提取独立章计划提案，再批准应用，才能据此起草。父规划或依赖版本改变后，需要重新确认相关章计划；当前是逐文件审批，不是批量原子定稿。结构无效或出处不匹配的模型JSON不发布，可修正回填，不自动重调付费接口。

关系图与时间线展示的是规划，不能把将来发生的事件、秘密或伏笔当作正式记忆。实际记忆仍依据作者定稿。查看[规划工作台审计](docs/planning_workbench_v3.md)与[数据契约](docs/blueprint_schema_v3.md)了解范围与后续工作。

## 配置 API

以下为尚未迁移的单API方式。启用多模型注册表后，任务改用「模型与角色」内的独立配置与角色绑定，旧单API文件及其环境变量不再覆盖新表。首次使用多模型时的迁移步骤见下方“多模型配置与职责绑定”。

点击 Studio 的「模型与 API 设置」，选择 DeepSeek、MiMo、GLM、豆包或自定义兼容接口，再选择或填写模型 ID 和 API key。密钥使用密码输入框，保存后清空输入，已保存密钥只显示配置状态。留空保留原密钥；勾选「清除密钥」删除本机配置中的密钥。更换接口地址时须提供新密钥或明确清除旧密钥。预设模型是填写建议，实际可用性以服务商控制台为准。

在同一弹窗填写「输入价格」「输出价格」，单位均为**美元／百万 Token**。按当前模型的未命中缓存输入价及输出价填写；人民币报价须先换算。留空代表未知，有美元硬预算的研究会要求补齐，不自动猜价。更换接口或模型后需重新填写对应报价。已启用多模型注册表时，弹窗会引导到「模型与角色」编辑实际使用的模型配置。

设置保存到工作区 **`config/api.local.json`**，不需重启，也不自动发起模型请求。多个页面或手工修改发生冲突时，须重新读取配置后再保存。仍可将 `config/api.example.json` 复制到该路径，手工填写 UTF-8 JSON：

```json
{
  "default_provider": "api",
  "api": {
    "base_url": "https://api.deepseek.com",
    "model": "deepseek-flash",
    "api_key": "",
    "price_input_usd": null,
    "price_output_usd": null
  }
}
```

换服务商时填写对应的 OpenAI 兼容 Base URL、实际模型 ID 和 API key。JSON 不支持注释，请保留双引号。密钥文件及其备份已加入 `.gitignore`，不要把真实密钥填入会上传的 `api.example.json`。未配置时提示填写 API，不回退到其他执行方式。

参考书架的「逐章研究」按页面标出的顺序操作：选章段、计费作品及金额上限 →「预览范围、模型与总预算」→ 核对费用后「保存研究批次」→「开始研究（付费）」。页面始终展示后三项操作和未满足的条件；预览与保存均不发送模型请求，只有明确点击开始才执行。变更范围、模型、价格或授权后需重新核对，不能使用旧预览继续付费。

以下为 2026-10-18 核实的普通按量 API 填写示例，实际权限和模型 ID 以各自控制台为准：

| 厂商 | `base_url` | `model` 示例或填写方式 |
| --- | --- | --- |
| [DeepSeek](https://api-docs.deepseek.com/zh-cn/) | `https://api.deepseek.com` | `deepseek-flash`；也可按已开通模型改为 `deepseek-v4-pro` |
| [小米 MiMo](https://mimo.mi.com/static/docs/quick-start/summary/first-api-call.md) | `https://api.xiaomimimo.com/v1` | `mimo-v2.6-pro` 或 `mimo-v2.6-flash` |
| [智谱 GLM](https://docs.bigmodel.cn/cn/guide/develop/openai/introduction) | `https://open.bigmodel.cn/api/paas/v4` | 例如 `glm-5.3`，按实际开通模型填写 |
| [豆包 / 火山方舟](https://github.com/volcengine/volcengine-python-sdk/blob/master/volcenginesdkexamples/volcenginesdkarkruntime/completions.py) | `https://ark.cn-beijing.volces.com/api/v3` | 复制控制台调用示例中的 `model`，通常为 `ep-…` 推理接入点 ID |

应用自动追加 `/chat/completions`。这几家共用同一适配器，已测试兼容协议；本次未调用其真实付费服务。上表使用普通按量地址；MiMo Token Plan、GLM Coding Plan 等套餐可能有专用地址、密钥和使用范围，请以对应套餐官方说明为准，不混用套餐与按量密钥。

未迁移的单API方式也兼容启动后端前设置环境变量，**环境变量按字段优先于旧 JSON**；若旧文件修改未生效，先检查是否仍设置了对应环境变量。启用多模型注册表后不再使用这些环境覆盖：

```powershell
$env:VIBENOVEL_API_BASE = 'https://你的兼容接口/v1'
$env:VIBENOVEL_API_MODEL = '服务商提供的模型ID'
# 用隐藏输入读取 key，不把实际 key 写进命令历史或项目文件
$studioApiKey = Read-Host 'API key' -AsSecureString
$env:VIBENOVEL_API_KEY = [System.Net.NetworkCredential]::new('', $studioApiKey).Password
.venv/Scripts/python.exe tools/studio.py
Remove-Item Env:VIBENOVEL_API_KEY
```

支持 OpenAI 兼容 `chat/completions`，不保证每个服务商所有扩展参数兼容。仅点击开始任务才调用；返回文本只保存到候选或审稿文件，不提供模型文件/Shell 工具。外部接口要求 HTTPS；本地兼容服务须在设置页启用本机回环地址，或设置 `VIBENOVEL_ALLOW_LOOPBACK_API=1`。usage 仅展示服务商实际返回值，无报价时成本未知。输入密钥仅用于本机设置保存，不放入浏览器持久存储、URL、任务或日志；后端不会把已保存密钥返回页面。

## 写作检查

「审稿与检查」提供写前包、本地审稿、固定样章、历史检索，以及下方DSH章节介绍的用词与档案、跨章线索：

- **写前包**：选择有效的已批准章计划，查看前章承接、近期正文和摘要、实际状态/事件/伏笔、已确认设定与父规划。精简/完整模式均有预算，缺失与未纳入资料明确列出。章节起草使用同一装配逻辑，任务中可选择模式；生成时重新核对批准和来源版本。
- **本地审稿**：检查已保存草稿或正文的套话、长句段、字面重合及固定样章句长差异。报告保留行号、原句、相关来源及建议，可标记待处理/已处理/忽略；正文或依赖变化后报告失效，需重新分析。
- **固定样章**：作者显式选定 1–10 份认可的样章。保存版本快照；原文变化后提示失效，不自动替换基线或改用全书。
- **历史检索**：仅搜索本作品正式章节，返回原句、行号和版本。默认中文二元字组/词项匹配，也可切换可选本地BGE语义检索，安装见下文；最多扫描80份/8MiB，语义片段另有限额，遗漏明确列出。相似度不是剧情重复判定。

这些检查无需 API，产物只进入报告与本地分析配置。统计与命中都是编辑线索，不代表文学质量或一致性结论。设计吸收了 [dsh-novel-writer](https://github.com/siweina/dsh-novel-writer) 的有用思路，本轮以 VibeNovel 原生核心实现，未引入其 MCP 写工具、Node 运行依赖或模型资产。详见[集成设计与验收](docs/writing_analysis_v3.md)。

服务默认只监听本机，限制 Host/Origin、变更请求令牌和文档路径；这是单用户本地工作流，不是对同权限本机进程的人类身份认证或安全沙箱。需要校园网访问时，必须显式启用 `campus` 模式、配置精确 Host 白名单和 PBKDF2 Basic Auth；该模式目前不信任 `X-Forwarded-*`，也不替代 HTTPS、反向代理和校园网防火墙。不要把默认本地模式直接反向代理到公网。开发时 `npm run dev` 代理 `/api` 到 8000，使用同一台电脑访问；正式使用推荐前后端同源构建模式。远程部署边界和验收顺序见 [校园网与公网部署设计](docs/studio_deployment_design_v3.md)。

### 校园网模式（仅在网络边界和 HTTPS 已验收后启用）

先生成只允许所有者读取的凭据文件；密码不会出现在命令行、配置或日志中：

```bash
python tools/studio_auth.py --file /secure/vibenovel/studio.auth --username author
```

启动时必须绑定明确的校园网网卡地址，并列出浏览器实际使用的 Host。不要使用 `0.0.0.0`、`::` 或只配置其中一项：

```bash
vibenovel-studio --workspace <作品工作区> --frontend <studio/dist绝对路径> \
  --host <校园网服务器IP> --port 8000 --access-mode campus \
  --allowed-host <校园网服务器IP>:8000 \
  --basic-auth-file /secure/vibenovel/studio.auth
```

campus 模式对每个请求要求 Basic Auth，并继续要求写请求的 `X-VibeNovel-Token` 和 JSON；Host 不在白名单时直接拒绝。当前实现不信任转发头，因此 Caddy/Nginx 终止 HTTPS 时还需按部署设计完成可信代理/外部 Origin 方案，不能把此命令直接作为公网服务。未完成登录、TLS、CIDR 防火墙、隔离工作区和备份验收前，继续使用 SSH 隧道入口。

## 快速使用

在项目根目录执行（ID 使用小写 ASCII，中文书名用 `--title`）：

```bash
python tools/vibenovel.py --help
python tools/vibenovel.py init my_story --genre adventure --title "我的小说"
python tools/vibenovel.py list
python tools/vibenovel.py import-outline my_story ./my_outline.md
python tools/vibenovel.py status my_story
python tools/vibenovel.py verify my_story
```

题材规则可选 `football`、`adventure`、`campus`、`alternate_history`、`general`。通用模块不提供四题材的专用检查；新通用作品使用project schema2，旧schema1四题材保持原样读取，不自动重写。新作品位于 `novels/my_story/`；不会迁移或覆盖根目录的 v2 资料。首次规划仍需作者确认，导入大纲也不会自动成为批准大纲。

默认严格 UTF-8，自动识别 UTF-8/UTF-16 BOM。旧编码需要明确指定：

```bash
python tools/vibenovel.py import-outline my_story ./old_outline.txt --encoding gb18030
```

原件按 SHA256 保留原始字节，与抽取文本、来源区间和 metadata 一起发布。重复内容复用首次来源记录；导入文本标为 `SOURCE / untrusted / canonical=false`。不执行原稿里的指令。应用不会覆盖原件；`verify` 能检出磁盘内容变化，但不提供操作系统强制只读保护。

## 正式章节导出

仅在作者已确认、正式章节存在于该作品 `chapters/ch001.md` 等文件后：

```bash
python tools/vibenovel.py export my_story --format md
python tools/vibenovel.py export my_story --start 2 --end 3 --output selected.md
```

输出限定在作品 `exports/` 中，默认不覆盖；显式 `--force` 可替换同名导出文件。章节按数字排序，缺章和重复编号报错；不导出草稿。M0 不提供自动定稿命令，也不代替作者判断目录中文件是否已经获批。按卷导出待卷归属结构实现后开放。

## 安装和配置

免安装脚本已可使用，也可以安装命令入口：

```bash
python -m pip install -e .
vibenovel --version
vibenovel --workspace /path/to/workspace list
python -m vibenovel --help
```

安装构建需 setuptools；运行核心仅用标准库。`--workspace` 放在子命令之前，默认当前目录，目录必须已经存在。CLI 配置读取该工作目录的 `config/app.json`，不存在则采用相同默认值；`execution.mode` 为 `api`，读取旧版 `codex_interactive` 元数据时归一为 API，不启用旧接力功能。其他未知版本、字段或模式均报错。Studio 的 API 任务使用前述本地 JSON 或环境变量配置。

```bash
python tools/vibenovel.py config
```

成功结果为 JSON（`--help`/`--version` 除外）；退出码 `0` 为成功、`1` 为完整性检查发现问题、`2` 为输入/配置/操作错误。`status` 的 `fingerprint` 是正式内容的当前指纹，不是批准记录或完整历史版本。`verify` 是磁盘完整性检查，`quality_review: not_run` 表示没有运行文学/连续性审稿。

## 已有小说分析与修订（3.0.0a6）

在侧栏打开「已有小说修订」，导入已经写好的MD/TXT整稿，或选择已保存的Markdown来源。先核对自动分章预览；前言会单独保留，特殊章标题可用原稿起始行手工校正。点击创建后生成独立修订副本，原件保留。每个会话最多80段/8MiB，每段最多20万字符；长稿可按卷导入。

选择章节，可运行本地检查、勾选多章或明确逐批检查全稿。每批最多20个目标/50万目标字符，对照当前修订会话的章节，显示实际覆盖和遗漏；本地检查提供套话、长句、作者词表、固定样章差异和跨章字面重合证据，不能认定整部小说无矛盾或可靠识别AI来源。

配置API后，可先做证据审稿，再选择「减少套话、减少重复表达、增加动作与感知、自然对话、保留原有文风」及保守/标准/深入强度，生成修改候选。拖选文本或输入Unicode字符区间可仅改选区；后端保留区间外的原文。审阅完整章节差异后，点击「接受到本章修订副本」，复查并独立导出。来源、候选、配置或参照版本变化会阻止接受旧候选。

这里的“降AI味”是作者选择的表达编辑目标，不提供AI概率、检测分数或通过检测保证。API审稿/改写会发送界面列明的正文范围与表达参照给已配置服务商；本地检查不调用生成API。任何候选仍须作者核对，正式正文与故事记忆继续通过原审批流程更新。详见[已有小说修订设计与验收](docs/manuscript_revision_v3.md)。

## 多模型配置与职责绑定（3.0.0a7）

在侧栏打开「模型与角色」。已有单API用户先点击「复制原 API 配置」，将当前配置显式复制成 `default_api`；原来的 `config/api.local.json` 保留。然后添加所需模型、填写对应API key，并在本作品内分别绑定规划、正文、审稿、候选记忆角色。可以让一个模型负责所有角色，也可以选择不同服务商；每个生成节点由单一实际模型返回，后续修订可按允许主备选择并保留来源链。保存配置不会发出模型请求，界面不会回显已保存密钥。

真实多模型配置在工作区 `config/models.local.json`，已排除Git。希望直接填JSON时，可将 [models.example.json](config/models.example.json) 复制为该文件；仅在目标文件不存在时复制，已有配置通过页面修改。示例包含DeepSeek、MiMo、GLM、豆包四个空配置。分别填写实际model ID与各自的 `api_key`，并按服务商文档核实 `context_tokens`、`max_output_tokens`；示例数值不代表已验证容量。报价 `price_input_usd`/`price_output_usd` 按每百万Token填写，不清楚时保留null；豆包可填写自己的 `ep-…` 接入点。最后在页面保存角色绑定，默认 `default_api` 不会自动改绑到示例中的任意模型。

作品策略同时设置共享的最多调用数、Token预算、可选美元预算及允许备用顺序。默认只允许一次调用；编辑→审稿→候选记忆至少需要3次，技术备用和重试另占用调用次数，须先保存足够预算。金额未知会显示“未知”，设置美元上限时须提供对应模型报价。路由预览显示首节点实际主备模型、输入估计与上限，任务记录保存冻结快照；排队期间改配置会使旧任务停止，运行中的模型不会被设置页悄悄替换。普通任务明确重试沿用原预算组，不重置余额；工作流节点禁止从通用任务页重试，须核对原流程和不确定费用后明确新建。

技术备用只在作者列明的目的地、次数和剩余预算内处理限流或部分服务器错误；认证失败、超时和来源冲突会停止。取消、超时或重启不确定是否已经计费时保留预留，不自动再次调用。所有结果仍是候选，API审稿与候选记忆不代替作者批准，也不自动写入正式正文/记忆。完整持久化和预算边界见[存储契约](docs/storage_contract_v3.md)。
