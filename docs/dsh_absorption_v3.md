# dsh-novel-writer 实用能力吸收说明

日期：2026-10-19。上游对照固定于 `siweina/dsh-novel-writer` 的 `0408091c6a189d965b55bbb22a156523cd3cb189`（6.6.0），[20 项工具清单](https://github.com/siweina/dsh-novel-writer/blob/0408091c6a189d965b55bbb22a156523cd3cb189/mcp/README.md#4-工具清单20-个)。本文区分原生覆盖、部分覆盖与有意采用不同实现；不是安装插件、复刻全部界面或宣称长篇文学效果已通过验证。

## 吸收方式

VibeNovel 继续采用自己的 Python 核心、作品目录、版本与审批记录。借鉴开写包、固定作者样章、可定位改稿、用词档案、跨章提醒和本地 embedding 检索的工作方式，不把第三方直接写入工具接到真实正式目录。

正式正文、人物地点/道具/世界规则与实际记忆的变更仍通过单文件提案、作者批准与应用；新章先生成候选，已批准章计划是起草前提。多文件定稿事务仍待实施。人物/伏笔登记只是检查配置，规划包仍是未来策划，不能充当已发生事实。自动多模型路由仍停留在单独的设计文档，未随本轮开启。

## DSH 审计问题 A1–A5 的修复口径

| 编号 | 本轮处理 | 证据与验收场景 |
| --- | --- | --- |
| A1 记忆版本号误当章号 | 严格识别 chNNN 及明确版本/日期后缀；其他文件要求 JSON 顶层整数 chapter 或 Markdown front matter 的 chapter；冲突、日期猜测和无时点汇总省略 | `ch004_v1`、`ch004_2026`、日期文件、无章号汇总、明确 JSON/MD 章号与冲突章号有回归；明确未来章文件不读取正文。单文件内部混入未来陈述仍须人工核对。 |
| A2 提示额度挤掉重要警告 | 有界候选按严重性/优先级保留，输出各规则 found/returned/truncated | 前置大量普通提示与后置重合警告共存；截断不再被解释成规则已完整执行。 |
| A3 重复提示缺少历史证据 | 展示当前与相关历史原句、来源 hash 和行号 | 作者逐项对照来源，版本失效后停止旧行号跳转。 |
| A4 旧检索跳到新正文旧行号 | 结果显示来源版本；打开文档前再次核对 hash，失效时要求重搜/复查 | 跨窗口更改及重新读取后的旧结果保护；字面与本地语义结果均按版本处理。 |
| A5 写前预览与实际输入不一致 | 所选文稿统一纳入写前包；已在包内的同版本来源仅复用摘录，包外作者资料明确附加并受模式预算限制 | 前章超长开头不会在 compact 任务中偷偷全文补回；前章结尾只发送一次；额外文稿预览与实际截断相同。风格锚段与已附区间重叠也不重复发送。 |

写前包新增 `input_manifest`，列出 path/hash、材料角色、原文字符半开区间与行号、实际附入字符数。`future_plan` 是未来计划，`past_fact` 是已定稿历史证据，`confirmed_setting` 是已确认设定，`author_source` 是作者所选来源，`writing_rules`/`style_reference`/`style_statistics` 只约束表达。正式版本 revision、来源 hash、固定样章配置与写作工具配置 hash 共同约束任务发布；源文或配置变化时旧候选停止发布。

写前包的 compact/full 限额为 60,000/160,000 字符；真实提示还包含作者说明、项目规则和任务边界，任务另保存 `prompt_budget` 并执行 220,000 字符总限额。写前包预览不是 Token/费用估算，最终模型 Token 以服务商返回为准。

## 本地检索与跨章看板的实际边界

字面检索与 embedding 检索分别标识。embedding 使用固定版本与校验 hash 的公开模型资产，推理在本机完成；向量缓存是可丢弃派生数据，不存第二套正文或权威事实。来源原句始终从当前正式正文读取，结果绑定 hash、行号/列号，扫描文件/字节/块数上限与遗漏明确返回。模型安装下载不携带作品正文或 API 密钥。

写前包的自动旧章补充目前采用有界词项召回，仍不是 embedding 自动选材；近期章以外最多扫描 80 份/8 MiB，每份开头 12,000 字符，最多召回两份。本地语义检索可由作者单独查询与核对，未将任意相似段落自动升级为角色知识。

跨章看板只对作者登记的人物名/别名及线索词查找字面提及，并给出原句证据。姓名在回忆或转述中出现不等于本人在场；线索词重现不等于伏笔兑现。章计划与正文覆盖只说明是否有相应章号文件，不判定正文遵循了计划。足球文的赛程、积分、年龄、转会、合同、伤病等领域一致性仍应另建可靠事实与约束。

## 验证记录与后续验收

本轮测试总数、前端构建、浏览器和真实本地模型回归的最终记录统一见 `implementation_plan_v3.md`，避免将进行中的数字写成最终验收。专项覆盖严格时点、写前包/任务同源去重、配置/锚段漂移、原审批与恢复兼容、提示截断、证据位置、规则复测、检索缓存与过期保护。

诊断专项验证只返回固定字段、已知枚举与规范章节路径/hash：正文、书名、作者要求、任务提示、API 错误与凭据标记均不出现在结果中；未知类型/状态归 unknown，自由规则名不输出；损坏/超限输入在 omitted 或 invalid_metadata 明示；不更改正式指纹，不下载/加载语义模型。

这些协议与回归证明功能和数据边界，不等于整部真实长篇已完成文学验收。真实使用还需要作者在固定测试稿上评估：旧章改写后的召回率、合理呼应的误报、不同文体基线的适用性、人物与伏笔提示的有效比例。不能用“20 项已有映射”换算“20 项上游效果完全等价”。

## 仍未承诺的能力

未实施的部分包括：可靠的人物知情/OOC与因果自动判定、伏笔回收自动认定、九类句式/情感曲线/六维文学画像的一比一复制、全局词表自动传播、多文件正文/记忆事务定稿，以及自动多模型分工和动态路由。独立 API 审稿可以对提供材料提出有证据的意见，不能替作者定稿；任何后续扩大自动化仍须沿用来源版本与作者决策边界。
