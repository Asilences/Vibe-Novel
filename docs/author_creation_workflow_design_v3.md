## 2. 对作者想法的评估

建议纳入必做：增加“创意与定位”专页，用创作简报连接空白作品和第一版总纲；左栏改为以创作对象与过程为主。保留清晰的已有稿分支，避免所有人先补一套设定。

标签适合作为故事方向、读者预期与限制条件，不能替代人物目标、阻力、选择和代价。生成页应把“一句话想法”放在标签之前，细节渐进展开；不要求作者在开写前填写几十个项目。

作者已明确原文“清洁”指**情节类型**。阅读标签的情节类型和内容标签的情节使用同一词项引用，不让同一个“重生/经营”等选项产生两份互相冲突的设置。内容尺度不作为本轮额外必填项。

先生成可读、可改、可比较的初版总纲，再展开卷纲、人物等资料和有限章计划。首次操作不默认生成整部小说的数百个章纲，不自动串行调用写作、审稿和记忆模型。

## 3. 三种明确起点

创建入口统一为“开始新故事”，创建后自动进入对应页面；书库和空作品总览也展示同样的三种选择。

| 作者已有材料 | 入口与后续 | 不需要的前置步骤 |
| --- | --- | --- |
| 只有一个想法 | 从零构思 → 创作简报 → 初版总纲候选 → 作者修改/选定 → 展开规划 | 不必先建Markdown或指定内部路径 |
| 已有大纲 | 导入/粘贴大纲 → 检查来源 → 展开卷章和相关资料 | 不要求模型先重写原大纲 |
| 已有正文 | 导入正文 → 校正分章 → 独立修订副本 → 检查/审稿/改写 → 接受差异 → 独立导出 | 不要求先生成全书大纲、补齐设定 |

原件继续保真，来源文本不成为系统指令。纯空白手写仍保留，作为次要入口。

作品名称可用暂定名；文件夹ID默认本地自动生成并检查冲突，移到高级选项。模型未配置时也能创建作品、保存构思，设置后回到原位置继续。

## 4. “创意与定位”页面

建议以分区表单为主，顶部轻量步骤指示“故事想法 → 补充设定 → 生成预览”。允许跳过可选区、随时返回与保存，不用强制逐页完成。

### 4.1 字段

| 分区 | 字段 | 必填与交互 |
| --- | --- | --- |
| 一句话故事 | 想写什么人、遇到什么事；可写几段基本情节 | 生成时唯一必填的创作内容；保存草稿可空，最长4000字；支持只写粗想法 |
| 阅读标签 | 主分类、主题、角色、情节类型 | 主分类单选或“暂未确定”；其他多选，可搜索/自定义/移除；未选不默认推断性别或目标读者 |
| 内容标签 | 情节机制、情感走向、人设、世界观 | 同一概念复用词项ID；可选“不希望出现”；不使用标签命中数作为质量分 |
| 主角与叙事 | 主角名/暂名、身份与定位、目标、短板、单主角/群像、POV | 全部可未定；群像支持多主角；叙述人称与焦点角色分开，不用一个“主角视角”混合两者 |
| 金手指/特殊优势 | 有／无／未定；有时填写类型、能力、限制、代价、揭示时机 | 明确“无”与“未定”不同；无时隐藏能力表单；允许信息、技能、人脉等非超自然优势 |
| 开局与因果 | 时代、起始时间/范围、地点、开局身份与处境、引爆事件、主要阻力 | 日期可相对或模糊，不强迫架空作品填公历；信息不全保留待定 |
| 规模与走向 | 目标字数区间、预计卷数、每章字数、结局方向/开放程度 | 首次默认只生成总纲；篇幅估算只供规划，字数/章数矛盾时提示而非悄悄改值 |
| 文风与边界 | 基调、节奏、对话偏好、避用套路、不能改变的条件 | 允许先填少量；硬约束与可协商偏好分开；固定样章由作者另行显式选择 |

不把列出的所有字段默认展开。首屏优先显示故事想法、分类/少量标签和“补充主角与开局”入口，最多两列表单；更复杂项折叠。

### 4.2 标签体系

- 使用版本化本地词表，初期人工维护少量高频标签，允许自定义。分类是创作辅助，不声称与任何平台最新官方分类同步。
- 同一词项可出现在阅读/内容视角，底层保存同一个ID；例如“经营”不用保存成两个相互独立的作者决定。展示、排序和推荐不修改作者选择。
- 推荐结果先作为未接受建议，作者点击选择才生效；不自动添加“更商业”的标签。取消某标签应清除其选择，不删除作者自由文本。
- 对“无外挂＋系统流”“写实＋明显超自然”等组合指出差异，允许作者解释或设为待定；混合题材不能一律判错。
- 作者硬条件优先于推荐词；冲突时先说明并提供修改，不偷偷为满足标签重写主角或背景。

### 4.3 题材能力与标签解耦

“阅读分类”表达写什么，“题材规则模块”决定实际加载哪套写作规则。现有四模块是football、adventure、campus、alternate_history；任意标签不可直接拼接prompt路径。

完整开书入口应增加**通用创作规则**：未覆盖的都市、幻想、科幻等可显式使用通用模块，并显示“通用规则；尚无该题材专用检查”。不得静默把其他类别映射成校园或历史。

实施建议：专用resolver固定白名单；旧schema1四题材原样读取。新建通用作品使用明确的project schema2（字段结构可保持，`genre`新增`general`），新核心同时接受1/2，旧文件不自动重写。新版本失败不能降级成错误题材；需迁移预览与跨版本测试。标签、偏好及主角信息保存在独立简报，不塞入严格的project.json。

a7只支持四专用模块。a8已增加白名单内的`general`通用规则，新通用作品使用schema2，旧schema1四题材不自动改写；页面明确提示通用规则没有专用题材检查。

### 4.4 生成预览与结果

生成前展示：有效作者输入、未定项、待接受AI建议（不进入有效简报）、硬约束，以及本次规划模型、材料范围、一个规划节点的首调/最大技术尝试次数、共享Token预算和费用是否可估算。默认一次尝试；允许备用时展示策略上限与剩余额度，不能把一个节点说成保证只计费一次。默认只生成一个总纲候选，不默认比较多个模型。

按钮区分“保存构思”和“生成初版总纲”。保存、进入页面、刷新、返回、改标签都不自动调用API。修改未保存时提示先保存/显式保存后生成，发送内容与预览版本一致。

首版总纲建议包含：故事承诺/一句话梗概、主角弧线、核心冲突与代价、开局、主要阶段/转折、结局方向、关键设定和待作者决定项。可附卷结构建议，但不必强造完整人物表、每章剧情或几十条伏笔。

结果页在同一工作区显示总纲正文、作者条件核对和版本比较，主要动作是“修改候选”“保留为备选”“选用这版继续规划”。重新生成保留旧版，不覆盖作者修改。选用只表示后续规划依据，不是正式正文或记忆批准；再次点击生成应预览新的计费请求。

选定总纲后，作者选择下一步：“展开卷纲与故事资料”或“先调整人物/世界”。章计划继续按少量章节展开并单独批准。总纲选用、规划包应用、章计划批准、正式定稿分别显示状态，不合并成模糊的“完成”。

## 5. 左栏信息架构

推荐**分组创作导航**。流程指示表示建议顺序，页面可往返，不要求先补齐所有设定才允许写作或修订。

| 分组 | 入口 | 首批数据与交互来源 |
| --- | --- | --- |
| 作品 | 创作总览 | 当前阶段、近期文稿、待决定项、一个明确下一步；三种启动入口 |
| 故事设计 | 创意与定位 | 新简报、标签、条件、总纲候选 |
| 故事设计 | 大纲与卷章 | 全书—卷—章计划树；现有来源/规划包/章计划与审批依赖 |
| 故事设计 | 人物与世界 | 人物总表、关系、地点/组织/规则；复用同一规划包视图 |
| 故事设计 | 时间线与伏笔 | 两个清楚子页；区分计划发生与正式已发生，提供等价列表 |
| 故事设计 | 写作风格 | 作者要求、固定样章、词表/避用项；来源与版本可查 |
| 写作与校订 | 章节写作 | 当前章计划、写前材料、正文编辑、候选与版本 |
| 写作与校订 | 审稿与修订 | 本章审稿/局部改写、已有稿修订入口、候选对照/匿名盲评 |
| 作者决定 | 待审变更 | 原完整审批中心；在相关页面保留就地跳转与状态 |
| 底部工具 | 资料库、任务与费用、模型设置 | 原件、运行追踪、角色/主备与预算、本机密钥；清楚区分全局与作品作用域 |

“人物”“世界”“时间线”“伏笔”是否进一步拆成左栏独立子项，由分组展开状态决定；不同时平铺十几项。推荐初始只展开当前阶段，另一个可评审方案是“构思/规划/写作/修订”紧凑阶段栏＋页面内次导航。

人物/伏笔等先作为统一规划包的不同投影，保留稳定ID。后续增加按条编辑时，通过同一包的版本化补丁保存并预览影响；不能各建一份独立JSON再试图双向同步。来源变化后提供“受影响的计划/记录”列表，不自动覆写。

主栏呈现当前创作对象；右侧改为按需打开的“当前任务/资料”面板。生成总纲、规划、正文和修订的按钮留在各自页面，多模型策略归执行设置，不要求用户跳到技术页才会写作。

## 6. 人机功效与补充优化

1. **实际下一步**：空作品提示构思/导入；总纲候选提示修改/选用；规划待应用提示审阅；章计划失效指出来源；有效计划才提示起草。依赖有效状态决定，不按“文件存在”推定完成，不显示伪精确百分比。
2. **正文优先**：非编辑页默认关闭通用右栏；正文提供专注模式、可调字号/行距/行宽。正文建议16–18px，辅助字12–14px，关键审批/费用不放极浅色小字。
3. **半成品可保存**：显式保存、清楚的保存状态；将来自动保存若加入，应只保存作者输入草稿，不能触发API或把建议转为作者选择。切换作品/页面覆盖所有表单的未保存保护。
4. **模板从少量开始**：可选题材构思模板和空白模式；模板值先预览再应用，禁止用示例人物污染真实作品。作者可保存自己的标签组合。
5. **不确定项集中**：从简报/总纲/规划聚合“待决定”但保留原出处，逐项跳转；不让模型为了清空待办编造事实。
6. **局部重做**：总纲阶段可保留两个备选；后续只重做某卷/某人物时展示依赖差异，锁定作者条件。细粒度补丁属于独立开发项，首批不能用整包重生成冒充局部保存。
7. **可访问布局**：1024px优先单主栏＋可折叠导航；更窄屏改导航抽屉和任务抽屉。标签支持键盘搜索/删除，状态有文字，图谱有列表；焦点回到触发按钮。
8. **任务成本可见**：生成旁展示实际规划角色、预算及未知费用；模型设置可返回原任务。关闭网页不丢后台记录，重启不重放可能计费的请求。

这些是设计目标；本次C1/C2已落地部分及仍待完成部分见第10节，不能将整份建议当作已验收功能。

## 7. 数据、接口与权限设计

### 7.1 创作简报

推荐新增 `CreativeBriefStore`，权威源固定为作品内 `outlines/source/creative-brief.json`，通过现有DocumentStore的锁、历史和单文件journal保存。增加专用路径/严格schema校验，不开放任意JSON写入。Markdown阅读摘要由JSON即时派生，不维护第二份必须同步的权威源。

建议字段：`schema_version`、`novel_id`、`catalog_version`、`story_seed`、各分区结构字段、`constraints`、`unresolved`、条目的稳定ID及来源/作者决定元数据。总大小最多256KiB，标签每维最多20个、自定义名最多40字、长自由文本各设限；服务端与前端相同限制，明确提示超限而不截掉作者原文。

来源与决定分开：来源可为作者输入、词表选择、AI建议、外部摘录；决定为已选、未定、待接受、拒绝。AI建议接受后仍保留其AI来源，只有有效已选内容进入生成简报。未定序列化为明确状态，不用空值代表“无”。

简报是作者创作意图，不是已经发生的小说事实。引用它只能证明“规划输入如此”，不得自动升级为角色知情、正式记忆或历史事件。正文/外部材料中的指令不能改变模型、预算、审批或接口。

### 7.2 a8 API与任务合同

| 接口/能力 | 实施合同 |
| --- | --- |
| `GET /api/creation/catalog` | 返回版本化本地词表与实际可用题材模块；不读取秘密配置 |
| `GET/PUT /api/projects/{id}/creative-brief` | 返回/保存当前作品简报，不返回模型密钥；保存带expected_hash及历史版本检查，空草稿可保存，过期返回409 |
| `POST /api/projects/{id}/jobs/preview` | `kind=generate_story_outline`，先核对固定简报版本再返回规划路由及有效输入快照；只预览，不预留、不调用 |
| 新任务 `generate_story_outline` | 复用jobs、planner路由、冻结模型和持久预算；由后端解析固定简报和输出路径，不需要先有作者手写Markdown |
| 输出 | 独立候选 `outlines/proposals/story-outline-<jobid>.md`；任务记录简报来源/版本，不能覆盖旧候选、正式纲、正文或记忆 |
| 作者选用总纲 | 单独版本化的source-selection记录，保存精确路径/hash/history ID；选用候选变化后失效；不借此新增正式文件写权限 |
| 后续展开 | 显式将所选候选交给已有`build_blueprint`；继续整包审核、有限章计划及逐章审批 |

“选用总纲”实际保存在固定受管文件 **`reviews/creation-selection.json`**，复用DocumentStore锁、版本历史和单文件journal；C0建议的`.runtime/creation-state.json`未采用。记录保存来源文稿path/hash/history ID，以及生成稿所依赖的简报hash/history ID和任务ID。它不是新的事实权威源，不能只在浏览器localStorage记选择，也不能误用写前包配置作为选用状态。

选用记录属于需要保留的工作状态，不能作为可随意清理的缓存；作品备份应与任务记录一起保留。

该记录限制未来任务输入。由生成候选展开规划时，后端重新验证总纲、简报与选用链并冻结相应来源；继续沿用受管文稿的`source_hashes`和历史版本，不把任意`.runtime`路径塞入审批`dependencies`。本次审计明确：更换选用纲或修改简报后，旧规划的批准历史保留，但相关规划来源过期，不能继续提取新章计划；不自动改已定稿正文或记忆。生成包发布、崩溃恢复以及创建提案之间均校验冻结历史，恢复同字节不能复活旧包。更广的依赖影响预览仍属后续工作。

第一次生成只提交一个planner节点；不把`planning_count=0`塞进现有1–10合同，也不套用仅支持draft/rewrite的候选工作流。已有扩写、规划、修订保持兼容。

任务绑定简报hash/history ID、使用词表快照、规则版本、模型/角色策略和预算；保存或词表改变不会偷换已排队输入。简报变更使未发送旧任务停止；已发请求按实际情况保留用量或不确定预留，过期返回不发布为可用候选；已发布旧候选仍可查看。A→B→A不能复活旧版本。

首次提交使用幂等键；重复点击不产生第二笔请求。明确重新生成使用新键与预算预览，失败/超时/重启不自动再调模型。路由和预算保持现有后端门禁。
