# VibeNovel v3 资料中心设计：文献、素材与语言风格

日期：2026-10-19。状态：**a9已实施L1基础、L2-A/B核心闭环；其余为后续设计**。作者最初要求先设计，随后明确“开始实施”。本轮实现范围与设计差异以第14节及现行 `storage_contract_v3.md` 为准；下面保留原始设计与调研记录，不表示全部功能均已上线。

软件基础以 `implementation_plan_v3.md`、`storage_contract_v3.md` 为准；创作导航沿用 `author_creation_workflow_design_v3.md`。实现验收使用人工资料与隔离作品，不读取、整理或收录作者真实作品；拟议高级能力仍需单独实施和验证。

## 1. 设计结论

增加统一的**资料中心**，同时提供“个人资料库”和“本书资料架”。文献、素材、参考作品、语言风格等共享来源与引用机制，各自保留专门字段和使用方式；不做互不相通的文件夹或六套独立后台。

资料从收藏到写作的路径是：**收集 → 整理 → 用于本书 → 用于本次规划/写作/修订 → 查看引用与影响**。作者也可以直接建立一张素材卡，或从一个待研究的问题开始，不要求先整理完资料库。

人物、世界规则、伏笔、计划时间线和正式记忆继续由作品原有系统管理。资料中心展示关联，不再复制一份人物表或事件事实库。外部资料、模型摘要、作者笔记、未来规划和正式正文证据始终可区分。

## 3. 六类资源与补充工作流

| 库/视图 | 保存内容 | 典型用途 | 专有字段/约束 |
| --- | --- | --- | --- |
| 文献与考据 | 书、论文、政策规则、史料、新闻、访谈、专业资料 | 核查制度、年代、职业、地域与技术细节 | 作者/机构、版本、出版与获取日期、DOI/ISBN/网址（可空）、适用时间地域、相互矛盾来源 |
| 创作素材 | 生活观察、经历、场景、职业动作、地点/物件细节、感官、冲突、对白构想 | 把故事种子变为具体场景与可选择的发展 | 原始观察/原文摘录、作者转化、AI建议分开；适用场景、代价、限制、使用记录 |
| 参考作品与技法 | 作者选定的小说/剧本等作品记录、阅读笔记、开篇/悬念/节奏/人物弧线分析 | 学习结构方法，比较不同叙事选择 | 原作位置、观察、抽象技法、在本书的转化方向；不把独特桥段和表达直接拼接成新稿 |
| 语言风格 | 多套可复用风格方案、作者认可的表达规则、样段及反例 | 创作定位、章节表达约束、已有稿修订 | POV、叙述距离、句段节奏、对白、信息密度、感官、情绪表达、避用方式、适用与不适用场景 |
| 表达与术语 | 专业术语、规范称呼、别名、时代用语、易错词、个人偏好、姓名/称谓候选 | 用词一致，查找表达方向 | 词义/语境/年代、规范项/可选项/避用项、理由和例句；不全局自动同义替换，不强制每章命中 |
| 方法与模板 | 场景规划、人物动机、考据记录、审稿清单、章节设计等可复用表单 | 帮作者组织决策和检查 | 适用目标、步骤、输入/输出、局限；只有作者显式采用后才成为该次任务要求 |

六类是同一资料中心的筛选和专用详情视图，不各占左栏一项。某篇参考作品可以关联技法卡、风格卡及素材卡，原文来源只保存一份，派生卡互相链接。

另设三项工作流，而非继续增加“库”：

- **待整理收件箱**：新导入、粘贴、网址记录、作者速记；尚未分类也可以保留，不默认为任务输入。
- **研究问题/待核实**：问题、适用时间地域、已找到的支持与相反证据、尚缺材料、作者暂定结论、影响章节。允许“未查到/有争议”，不因有一条搜索命中就自动关闭。
- **专题收藏夹/素材包**：例如某联赛某赛季、某时代城市生活、某职业动作、某卷场景。是资源ID的集合，不复制正文；专题不是新的事实权威。

关系图作为后期的引用视图：来源支持哪条笔记、哪条素材用于哪章、哪个问题存在相反证据。先提供可靠列表与双向链接，再考虑图形展示；不与现有小说人物关系图混为一张图。

## 4. 个人库、本书资料架与四种动作

### 4.1 两种作用域

**个人资料库**面向当前工作区的作者，可跨书复用作者显式收录的资料、抽象技法和风格模板。“个人”暂不表示跨工作区账户、云端同步或多用户服务。

**本书资料架**保存只属于当前作品的素材、笔记，以及作者从个人库显式选入的固定版本。默认搜索本书；切换个人库需要明确动作。其他作品的正文、人物和设定不会自动被扫描或纳入个人库。

从书内“收藏到个人库”时，预览所带原文、笔记、来源及是否含剧情剧透；作者选择收录范围。个人库本身不公开、不自动进入 Git 或云端。

### 4.2 四种动作与结果

| 作者动作 | 改变什么 | 不代表什么 |
| --- | --- | --- |
| 收藏资料 | 将原件/卡片存入指定作用域 | 尚未允许用于任何作品或模型任务 |
| 用于本书 | 固定资源版本、建立书内用途和批注 | 不是本次任务输入，也不是事实批准 |
| 用于本次任务 | 作者手选，或按已保存的书级策略自动选取具体摘录/卡片、用途和范围，冻结输入版本 | 不批准模型输出，不修改章计划/正文/记忆 |
| 转为设定/规划提案 | 把作者改写后的内容和证据送进既有提案流程 | 不自动应用正式设定；涉及多文件仍受 M2 未实现限制 |

个人资源更新显示“有新版”，本书旧选择不自动跟随。书内批注由本书持有，不回写个人库。个人库更新与“用于本书”分两次独立保存：作品绑定完整可校验版本后才发布引用；失败不出现半条可用引用，不依赖尚未存在的跨库事务。

显式授权和版本冻结不要求作者每章逐条手选。作者可为本书一次配置允许检索与入模的范围、用途和预算，后续在该范围内自动选材；手动选择与排除用于覆盖自动结果。具体模式见9.3。

## 5. 作者在 Studio 中的页面与操作

### 5.1 导航

- 保持已选“分组创作导航”。辅助工具增加一个**资料中心**；原“来源资料”快捷入口打开资料中心的原件/收件箱视图。
- “正式记忆与资料”改为更明确的“正式设定与记忆”，保持可达，不与外部资料混在同一列表。
- “故事设计 → 写作风格”保留，呈现本书当前有效要求、固定样章、相关词项及来源；模板的收藏/比较在资料中心完成。
- 章节写作、总纲规划、已有小说修订增加可展开的资料选择面板，选入后回到原光标与未保存内容；不强迫离开正文来找一条资料。
- 无作品时仍可进入个人库；涉及本书动作时再选择作品。窄屏使用“列表 → 详情 → 返回”，不固定挤出第三栏。

### 5.2 资料中心布局

```text
资料中心                       [本书资料架 ▾] [搜索] [新建/导入]
待整理 | 全部 | 文献 | 素材 | 作品与技法 | 语言风格 | 表达术语 | 方法模板
筛选：专题 / 标签 / 年代地域 / 待核实 / 来源类型 / 使用状态

条目列表（主要区域）            选中条目详情（可展开/可关闭）
标题、类型、摘要、作用域         概览 | 原文与摘录 | 笔记 | 关联与使用
来源版本、待核实、用于哪些章节   用于本书 / 选入任务 / 建研究问题
```

首屏以搜索、近期资料和待整理为主，不要求先填写完整书目。卡片标题必填，类型与内容足以保存速记；来源、年代、许可、适用范围可标“待补充”。外部材料缺来源时仍可本地保存，但不能显示成已核实资料。

详情将“原句”“我的理解”“AI整理建议”分区。高亮摘录后能新建事实笔记、素材、技法或术语卡；切换卡类型不复制原始文件。打开来源能回到绑定版本和位置；原文件失效时打开保留快照并提示，而不是跳到当前文件的旧行号。

### 5.3 三条首要用户路径

1. **考据后规划**：新建研究问题 → 导入相关资料 → 摘录并比较依据 → 记录作者结论与未定项 → 选入本书 → 选入总纲/章计划任务。现实规则与作者虚构改动并列，不能暗中改写已批准规划。
2. **写作中调用素材**：在章节写作打开资料面板 → 按本章地点/职业/情绪搜索 → 查看原句与作者转化 → 选择少量卡片 → 预览实际输入 → 生成候选。使用记录仅表示供该任务参考，不证明成稿确实采用或事件已发生。
3. **已有稿统一表达**：打开独立修订副本 → 选风格方案/术语要求 → 确认适用目标及样段 → 预览并审稿/改写 → 比较候选。检查可观察的句式、信息组织、对白等，不给出“AI概率”或保证通过检测。

## 6. 语言风格库的专门设计

### 6.1 一套风格方案包含什么

| 项目 | 示例方向 | 使用方式 |
| --- | --- | --- |
| 叙事组织 | 第三人称限知、贴近焦点角色、信息逐步揭示 | 与本书POV/角色知情边界核对；冲突先呈现给作者 |
| 句段节奏 | 叙述中短句结合、关键决定处留短段 | 具体场景偏好，不强制全书同句长 |
| 场景与感官 | 通过动作/物件传达处境，有选择地写声音与触感 | 给可执行建议，避免机械“每段必须五感” |
| 对白与角色语域 | 口语省略、人物职业词、潜台词和动作间隔 | 角色语域附属于本书角色，不从外部样文导入人物身份 |
| 情绪与修辞 | 减少重复情绪命名、控制比拟密度 | 保留原文语境，不靠批量替换词语改稿 |
| 正例与反例 | 作者自写或明确选定、带位置的短段及解释 | 标明学什么/避免什么；不把样段剧情作为故事事实 |
| 范围与例外 | 全书基调、某卷、动作场景、对白场景 | 一个主方案，可显式选择局部补充；冲突显示差异而非静默叠加 |

不以“像某作家”作为唯一可执行目标；可从作者选定样文提炼叙述距离、节奏、感官取舍等抽象特征。抽取结果是候选，作者可修改后保存模板。外部样文、作者自有样文及AI示例分别标来源。

### 6.2 与现有风格能力的关系

现有三种角色分别保留：创作简报/规划包中的文风是意图和未来规划；toolkit 是作者显式有效表达要求；固定样章是作者选定版本的统计基准。新增风格模板只是可供选择的资源，不自动成为第四套生效规则。

拟议 L2 提供显式“采用此风格方案”预览：对比现有要求，作者选择替换或逐项合并，保存一个书级有效选择与版本。实施时确定统一有效规则读取层，迁移后旧 toolkit 规则编辑入口改为同一数据的视图/兼容适配；不同时双写两份可独立修改的权威规则。人物名/伏笔检索登记等原 toolkit 其他职责保持独立，不因采用风格模板被清空。

固定样章选择仍独立、显式，只接受现有合同支持的本书 chapters/drafts；外部风格卡不能绕过此限制冒充作者基线。自有跨书样段可以成为表达参照，但不自动变成统计基线。扩展基线来源必须另改合同并验收，不通过把外部小说复制进本书草稿来规避。

迁移前原a8模式完整有效，不偷偷创建或启用新选择。采用方案涉及已批准规划中不同文风时，呈现差异并另走规划修改提案；不直接重写父规划或令已有章计划自动获得新批准。

## 7. 来源、卡片与引用的数据设计

### 7.1 核心实体

| 实体 | 拟议最小字段 | 说明 |
| --- | --- | --- |
| Source 原始资料 | stable ID、作用域、原件hash、抽取版本/hash、格式、书目信息、获取信息、处理覆盖 | 原始文件和抽取内容不可被笔记覆盖；同字节可有不同书目身份/版本记录 |
| Entry 资料卡 | stable ID、类型、标题、正文、标签、作者/来源/模型归属、状态、revision/hash、来源引用 | 卡片属于作者或候选整理层，不是世界事实 |
| Excerpt 可定位摘录 | source ID与精确版本、抽取器版本、区间、原句hash、原句及定位信息 | 摘录定位指向原始版本，不随重新解析静默移动 |
| Collection 专题 | ID、名称、说明、资源ID/版本引用 | 不重复保存正文 |
| ResearchQuestion | ID、问题、适用时间地域、证据引用、相反证据、作者结论、未解决项、状态 | 来源核对与结论可信度由作者判断，不输出无依据的可靠度分数 |
| BookBinding 书内选用 | 本书ID、资源ID/版本、用途、书内批注、可见范围、来源状态 | 固定版本；个人库更新只提示 |
| StyleSelection 风格选择 | 主方案/局部项的精确版本、作者合并后要求、适用范围、旧配置来源与迁移记录 | 未来有效规则层；不能与旧规则并行成为第二权威 |
| TaskReferenceManifest | 任务ID、绑定/条目/来源版本、用途、实际区间、快照hash、包含/遗漏原因 | 记录实际发送内容；与任务路由、预算及来源依赖共同冻结 |
| Usage 使用记录 | 哪次任务/提案/导出引用何版本、生成时间、作者标记 | “已发送参考”“作者标记采用”“正文证据确认”是不同状态 |

卡片至少分离以下维度，不用一个“已批准”覆盖全部意义：整理状态（待整理/可检索/归档）、来源归属（作者笔记/原文摘录/AI建议）、核对状态（未核对/核过原文/待补证/有争议）、任务使用政策。模型不得自填成“作者已核对”；保存模型建议也不自动启用。

“核过原文”只证明摘录或笔记与材料对应，不保证材料真实、完整或适用本书；多个相互复制的网站不能当作多个独立证据。允许给判断记录支持、反驳及版本，不以多数票消除冲突。

### 7.2 原文定位

- MD/TXT：保持解码与换行约定，使用 Unicode 码点半开区间和1起始行号；前端UTF-16索引显式转换。
- DOCX：后期保存段落/表格单元格路径与抽取区间，不伪造不存在的稳定打印页码。
- PDF：后期保存物理页索引、可选印刷页码、文本块/边界框和抽取区间；阅读顺序/多栏表格遗漏明确记录。
- 网页：初期只登记网址与作者粘贴片段；后期主动获取才保存时间、规范URL、快照hash和段落定位，去掉活动脚本；链接存在不等于已经读取全文。
- OCR/图片：后期保存页/区域、识别文本、校对状态；低置信或未识别区标为遗漏。图片作为观察参照，不能据此自动得出角色/年代等确定事实。

同一原件有不同抽取器版本时，建立独立 rendition。hash去重不能把不同解码或抽取版本覆盖成同一条；摘录永远绑定生成时的精确 rendition。

## 8. 拟议存储与一致性合同

以下路径**本轮不创建**，不属于现有 DocumentStore 白名单。拟议专用 LibraryStore 与 API 处理资料；不开放任意本机路径，不直接扩大通用文稿写入权限。

```text
<workspace>/library/                       个人库，未来须默认排除Git
  library.json                            固定库UUID与schema
  sources/<id>/versions/<version>/         保真来源与独立抽取版本
  entries/<id>/...                         版本化资料卡
  collections/<id>/...
  research/<id>/...
  .state/                                 版本/journal，权威运行记录
  .cache/                                 可重建SQLite/向量缓存

novels/<id>/library/                       本书私有资料与固定绑定
  sources/...                             仅本书的新增原件（如有）
  entries/...                             本书素材与笔记
  bindings/<id>/...                        所选资源身份、版本、用途
  snapshots/...                           选用的资料卡及必要来源快照
  research/...                            本书研究问题
  selections/...                          显式风格/资料集合选择
  .state/                                 库级历史与恢复意图
  .cache/                                 派生索引
```

1. Markdown/JSON及保真来源版本为权威；SQLite全文索引、向量及图视图是可重建派生数据。`.state` 与预算/journal一样不能作为缓存清空。
2. 先定义独立的library schema1及schema迁移，不通过自动改写旧project.json或根目录v2资料获得兼容。旧`imports/original`可以由新条目引用；需要可移植快照时显式导入并记录来源，不修改旧bundle布局。
3. 单库保存使用 expected_hash + 单调revision + 同盘原子发布/恢复意图；多对象入库采用暂存包与最后发布的清单，失败不展示“已完整入库”。任务用不可变的书内冻结快照，避免跨库持锁等待模型。
4. 新版资料不改写旧引用。书内“更新到新版”先显示引用/风格/任务影响，再生成新绑定版本；旧任务不自动重放。模型调用开始前冻结版本，来源实质失效则按依赖规则阻止旧候选成为当前可用版本。
5. 区分**固定旧版可用、有新版待选、引用损坏、来源被撤回、有效选择被替换**。仅发布新版不使固定旧版自动失效；撤回/禁用或已选绑定变化需要阻断使用并保留原因。应用内观测到的A→B→A不复活旧选择；未观测到的外部回写继续不承诺可检测。
6. 已完成任务保留历史输入快照与状态；后续来源被撤回不重写历史。作者使用旧候选继续编辑/提案时重新核对当前依赖。已定稿正文永远不因资料更新被自动改写。
7. 删除默认归档/回收；仍被引用时给出影响清单，保留ID墓碑与历史定位。确需清除内容时，相关引用明确显示缺失，不能继续从索引/嵌入缓存返回已清除原句。缓存按作用域/版本定向失效。
8. 备份作品时包含本书已选版本与必要出处，可单独阅读；不自动打包整个人库。按政策不允许携带的来源保留书目和缺失清单。导入备份遇相同ID但内容不同须显式处理，不覆盖本机库。
9. 在首次实现创建资料文件前完成Git忽略、备份与日志范围约束；私人原件、摘录、索引、任务快照不进入公开仓库。例子与测试只用人工可分发假资料。

## 9. 检索与模型使用

### 9.1 检索不是事实确认

初期先做标题/标签/书目/卡片正文/摘录的精确与词项检索。中文需测试分词或二元词项，不直接假定SQLite默认分词可用。随后增加可选的本地语义召回和混合排序；优先复用已审计嵌入引擎，另建 library corpus adapter 与独立缓存，不扩大现有 `_history()` 的扫描范围去偷偷搜索所有作品。

默认查询本书已选资料；查询个人库时明确显示范围。结果分开呈现文献、灵感、表达参照及正式正文证据，返回ID、版本、原句位置和实际扫描/遗漏范围。全文、词项和embedding模式各自标识，不无提示降级。重复检索同源材料合并展示出处，不把重复次数当可信度。

模型可以建议查询词、整理卡片、抽取术语、比较来源、提出研究问题和抽象文风；每次生成遵循现有角色路由、冻结配置、预算和候选发布。模型不得伪造来源ID、页码或作者核对结论。找不到证据时返回“未查到/待核实”，不补一个看似真实的引用。

### 9.2 写前/规划/改稿选材

任务引用用途至少有：**现实知识参考、灵感素材、结构技法、表达参照、用词偏好、方法模板**。这些用途不能被模型升级为“既有故事事实”。正式正文/记忆仍按原过去时点规则装配，资料库引用不绕过章计划审批。

选入任务时预览：资源名和版本、用途、实际摘录、未附范围、有效作者要求、模型目的地、估算预算。相同来源重叠区间去重；可选资料先截断/省略并显示原因，必需作者所选材料超限则拒绝或让作者调整，不静默换成摘要继续发送。

历史题材另记录资料适用时间和角色获取信息的时点。发表年代不等于事实发生年代，来源描述真实未来事件也不等于开局角色已知；主角有无未来知识依据作者已选设定。叙述者视角和角色知情边界分别处理。

资料卡的“本地保存”与“允许发送”分离。建议用途政策为本地分析、仅发送作者摘要、可发送所选摘录；由作者按来源/卡片明确选择，并在任务预览显示。初期外部新收录材料默认仅本地，不把一次导入当作对所有厂商永久开放。版权/来源许可保留为作者记录，系统不自行宣布外部作品可再分发。

已选资源要显式生成书内任务快照，含精确来源、版本与用途；将库资源标识接入依赖合同，不靠把字符串伪装成当前允许的文档路径。预览、排队、发送、迟到结果发布、人工恢复均核对有效选择及快照，沿用幂等与不自动重放未知付费请求的规则。

### 9.3 自动调用：书级策略，任务级记录

资料库应支持AI/后端按任务自动检索与装配上下文。当前a8只在写前包中有限自动召回本书更早定稿（`core/briefs.py:264`）；不检索新设计的文献/素材库，也没有自动把本地语义搜索结果装进写前包。新能力仍待实施。

| 模式 | 系统行为 | 作者操作 |
| --- | --- | --- |
| 手动 | 只使用本次固定资料及有效作品要求 | 自己选择补充资料 |
| 自动推荐 | 在允许的本地范围按章计划/修订目标检索，给出相关片段及原因，尚未加入模型输入 | 在原有生成预览中接受、删除或调整推荐；建议作为未启用自动选材时的默认模式 |
| 有界自动 | 在本书已绑定、允许相应用途和外发方式的固定资料版本内检索、筛选、去重并加入输入 | 书级启用一次；后续无需逐条重复确认，仍可在任务预览中覆盖 |

拟议书级 RetrievalPolicy 保存模式、允许专题/资料类型/用途、固定必选、排除项、片段数与总字符上限、外发政策及是否允许额外模型检索规划。任务记录policy revision/hash、实际查询、所选版本/区间/用途、选择原因及覆盖/遗漏。选择原因由检索与装配过程生成，不把模型自报相关度当正确性证据。

作者固定必选、有效风格要求和已批准章计划优先，自动候选仅使用剩余预算。必要材料无法容纳时显示问题，不以自动检索替代必需章计划。研究事实、灵感、表达参照分别筛选；正式历史按时点装配，外部未来知识仍受角色知情边界限制。

建议自动检索在作者发起规划/写作/修订时进行，保存/翻页不触发额外付费推理。默认以任务目标和章计划本地组查询；若需模型改写查询、逐轮工具检索或重排模型，须在配置及预览中声明调用次数与共享预算。自动模式不意味着无上限Agent循环。

自动化持续适用已有书级范围；检索到未绑定个人资料、未允许外发内容或需要扩大用途时，可列为本地建议，不静默发送。是否改用新资料版本、启用新风格或扩大范围仍由作者决定；原定模型目的地及预算合同继续适用，常规范围内的检索不新增逐片段审批。

### 9.4 RAG索引与最小架构

RAG指任务中检索有关材料再辅助生成，并不要求一开始就部署向量数据库。资料中心应提供这条使用路径，而不止是人工文件管理：

```text
原件/作者卡片 → 有来源与位置的段落/小节 → 元数据与词项索引
                                             ＋ 可选本地向量索引
任务目标/章计划 → 作用域、用途和时点过滤 → 召回与去重/排序
                → 按预算装配资料包 → API生成候选 → 引用与输入记录
```

第一步以SQLite可重建元数据/全文索引及中文词项策略支持精确召回；L2即可用词项RAG打通自动选材。第二步增加可选本地embedding并做词项/语义混合召回；复用现有已审计引擎，但新建资料语料适配器和独立缓存。没有embedding时仍可明确使用词项RAG，不把它标成语义检索。

索引按逻辑语料分区与过滤：本书正式历史证据、本书所选外部文献/素材、已选技法/表达资源各有用途，不需要为每类部署一个数据库。全书主文风和规范术语等小型确定要求优先直接装配，不依赖相似度碰巧召回。个人全库仅在作者切换检索范围时查询，不遍历其他小说。

切块优先段落/小节并保留标题上下文；确需重叠窗口时记录精确区间。索引键至少绑定作用域、资源/来源版本、抽取与切块版本，向量另绑模型版本；持久保存前复核来源，返回原句时回查对应权威版本。解析缺失、未建索引、扫描限额和过滤原因明确展示。

初期无需独立Chroma/Milvus服务或图数据库。先以中文测试问题核对关键术语、改述查询、年代、相反证据、合理呼应与跨书隔离，记录召回、错误及耗时，再依据规模决定是否需要专用向量后端或重排模型。不能仅以“已有向量”验收效果。

### 9.5 Book2Skill：把方法提炼为可用资源

Book2Skill不是唯一项目名。按作者“尽量找热门或高星项目”的要求，主要候选改为 **book-to-skill、Skill Seekers、Cangjie**，具体热度、分工及一手资料见9.6。本轮查阅官方README、架构/技能规范及部分包声明，不代表已做完整源码、安装或效果审计。

作者随后同意由我们选择合适机制并更新设计：首批确定吸收book-to-skill的组织流程与Cangjie的方法卡/验证机制，Skill Seekers局部格式管线延后L3/M4；不是把三套运行时整体装进Studio。具体页面、API接入、方法状态及阶段出口见9.7和 `studio_skill_absorption_design_v3.md`，功能仍待实施。

有用的部分是**来源 → 阅读地图 → 方法候选 → 核对依据 → 作者选用 → 按场景加载**。适合将写作教程、职业方法、场景设计与审稿方法转成库中的“方法与模板卡”；普通事实资料主要保留给原文与RAG，小说参考作品优先提炼抽象技法/风格卡。生成的候选包含适用情境、必要输入、步骤、输出、局限、来源定位和抽取覆盖，不把少数深读章节标成整书已掌握。

方法卡在L2增加可选的显式API抽取入口；先输出候选，经作者采用后才能被相应任务自动加载。初版只加载声明式步骤与表达要求，不执行导入技能中的脚本、安装命令或任意工具权限。方法中需要证据时可以继续RAG查询原文，抽取产物不替代保真来源，来源变更按固定版本策略处理。

Studio直接调用API；仅把SKILL.md安装进Codex/Claude目录不会让DeepSeek、MiMo等API自动发现它。NovelCore须负责匹配方法、加载需要的章节/步骤并装配提示，或另实现受控工具调用协议；不会因此恢复已移除的Codex交互接力。未来可导入/导出受限SKILL.md资源，但不把第三方技能宿主设为首版依赖。

技能抽取不等于微调模型，也不保证模型正确掌握整本书。不默认把资料全文发送给外部生成器、不照搬第三方下载/安装链；是否复用具体转换器及其解析组件，待源码、许可、定位质量、依赖和效果评估后另决定。当前不安装任何项目。

后续源码审计与试点的建议顺序：

1. **book-to-skill学习组织方式**：确定性抽取与语义生成分开；保留来源版本、章节映射及实际阅读覆盖。原件之外的清洗/规范化结果保存为独立抽取版本，不能覆盖原文定位。
2. **Cangjie学习方法卡和验收**：区分原文、解释、原书案例与合成练习，写清何时使用、输入、步骤、输出、边界和反例；有依据但不可执行的内容留作参考，有缺口的留待核查，不强制每章生成若干技能。方法卡继续属于9.5的候选资源。
3. **Skill Seekers学习资料工程**：评估多格式/多来源合并、冲突展示、增量更新及技能/RAG不同出口；按实际需求复用局部适配器，不首期整体嵌入其运行环境。
4. **少量真实任务验证**：未来在作者明确选定材料上，冻结来源、模型与预算，比较有/无方法卡的场景规划、人物动机审稿等代表任务。分别记录引用正确性、遗漏、能否完成任务、外发与成本；能检索/触发不等于执行正确，少量样例也不证明文学质量整体提升。本轮不运行这些试点。

Book2Skill与RAG互补：前者把可迁移方法整理成任务步骤，后者按需取回事实证据、术语定义、原书上下文或边界说明。小型有效规则直接装配，大型方法资源先匹配入口再加载必要内容；不把所有技能全文塞入每章提示，也不把只做向量索引称为方法提炼。

定向核查的一手文件：[book-to-skill架构](https://github.com/virgiliojr94/book-to-skill/blob/master/docs/architecture.md)与[包声明](https://github.com/virgiliojr94/book-to-skill/blob/master/pyproject.toml)、[Skill Seekers说明](https://github.com/yusufkaraaslan/Skill_Seekers/blob/development/README.md)、[Cangjie方法规范](https://github.com/kangarooking/cangjie-skill/blob/main/SKILL.md)、[Fabric提取模板](https://github.com/danielmiessler/Fabric/blob/main/data/patterns/extract_wisdom/system.md)、[Docling说明](https://github.com/docling-project/docling/blob/main/README.md)、[MarkItDown说明](https://github.com/microsoft/markitdown/blob/main/README.md)。以上链接指向活动分支；未来复用前固定具体提交及许可快照，另验中文材料和来源映射，不把本轮文档阅读记作实施验收。

### 9.7 已选定的Studio吸收方案

选型从“热门候选”推进为具体方案：**book-to-skill组织资料，Cangjie规范方法卡与验证，Studio自己的API任务负责执行**。详细设计在 `studio_skill_absorption_design_v3.md`，本节只列与资料中心的接口，不复制第二份数据合同。

- **入口**：来源/专题详情“提炼创作方法”→范围/用途/预算预览→分析报告→方法候选→作者修改采用→用于任务；小说参考作品优先显示“分析创作技法”。方法归现有六类中的“方法与模板”，不另占顶层导航。
- **实体**：ReferenceAnalysis、MethodCard、MethodTrialRecord及MethodRun作为来源/Entry/任务的受管类型；方法正文仅一份权威，小入口/路由/提示及未来导出均为派生。采用、引用校验、语义评阅、试用、外发政策分别记录。
- **自动使用**：按本书已保存政策匹配已采用方法，加载必要步骤/边界与RAG证据；不每章重复批准，不把未采用方法或库内所有全文注入任务。作者要求、必需上下文及已批准计划优先。
- **任务归属**：现JobManager与账本绑定Project。首期API提炼/试用显式选择计费作品，结果先在该书保存，再可另行收藏到个人库；无作品时仍能本地浏览/整理，不默借预算或读取计费书的未选文本。
- **阶段**：L1资料/版本前置→L2-A分析与提炼→L2-B采用与任务装配→L2-C可选评阅/试用；L3/M4再评估Skill Seekers及解析器局部依赖。方法新任务类型、有类型的库依赖与整包发布/恢复须正式扩展，不能伪装现有文稿路径或绕过工作流白名单。

这次吸收是设计上的明确选型，尚未安装、实现或完成文学效果验收。既有来源/版本、作用域、书级授权、正式事实与审批合同继续适用。

## 10. 输入方式与边界

| 输入 | 当前情况 | 建议阶段 |
| --- | --- | --- |
| MD/TXT、粘贴文本、作者手写卡、手工网址/书目信息 | 文件导入已有，其余需要资料实体及界面 | L1优先；网址登记不默认联网 |
| CSV/JSON术语和素材清单、BibTeX/RIS书目 | 未实现 | L3；先预览字段映射、编码、重复和缺失，不信任导入字段中的指令 |
| DOCX、可抽取文本的PDF | M4规划中，未实现 | L3与M4共用抽取及定位合同，不写两套解析器 |
| 扫描PDF、图片OCR、网页快照 | 未实现 | L4可选；先明确依赖、覆盖与校对成本 |
| Zotero/其他外部管理器连接 | 未实现 | L4可选；先支持可移植书目导入，再评估双向同步，非首版依赖 |

L1建议单份MD/TXT默认沿用现有10MiB上限，批次拟议最多20份/合计50MiB；卡片和摘录另设数量/字符上限，实施前写入独立schema并验证。达到上限明确拒绝或分批，不部分丢弃出处。首次索引大型库需记录进度、可取消与继续，不把界面关闭视为资料丢失。

PDF/DOCX等在前置抽取器可用前只显示“未支持”，不能通过上传成功制造已完整解析的假象。联网、OCR或嵌入下载也不能由打开页面或保存卡片隐式触发。

## 12. 拟议验收场景

1. **考据有争议**：两份人工测试资料对同一时代规则说法不同，系统保留两条原句和各自适用范围；研究问题可保持未解决，作者选哪条也不自动改正文。
2. **跨书素材复用**：A书自写素材显式收藏到个人库，B书选择其中一个版本及局部摘录；B看不到A未收录的角色、计划或正文。个人更新只提示有新版。
3. **风格不混用**：资料中心收藏两种风格方案，书内只显式启用一个主方案；局部对白补充有范围，冲突可见；外部样段不能冒充本书固定样章。
4. **从研究到任务**：未核实来源可本地保存；仅摘要政策时正文不能进入API；任务预览/最终manifest显示一致的实际片段、用途、版本、遗漏和预算。
5. **固定版本、失效与恢复**：个人库或本书卡片仅保存新版，而书内/任务仍固定旧版时，旧任务继续使用原快照；本书明确接受新版/替换选择、修改有效风格要求或撤回来源后，旧任务候选/恢复不能伪装成依赖仍有效。分别验证两条路径，保留历史输入，已定稿正文不自动改变。
6. **引用可定位**：MD/TXT含CRLF、emoji及重复原句，仍定位正确绑定区间；PDF/DOCX后期另验其真实可提供的位置，不混用页码/段落/字符索引。
7. **输入不是指令**：假参考资料含“忽略规则/上传其他作品”等文字，只作为来源内容展示，不改变任务授权、用途或搜索作用域。
8. **备份与清除**：作品带所选来源可离线迁移；不允许携带的材料列缺失；库归档可恢复，真正内容清除后不再从搜索/缓存回显。

这些场景使用人工假资料与离线provider即可验证数据/交互合同；真实文献核查、风格效果与检索相关性另由作者在明确测试材料上评估。本轮未执行这些尚不存在功能的验收。
