# Studio远端运行手册

更新：2026-10-22。正式作品与资料库已恢复到用户级常驻后端；服务器仅监听`127.0.0.1:8000`，本机固定访问`http://127.0.0.1:18000/`。没有配置公网域名或HTTPS站点。

部署实况与验证范围见[部署设计第8节](studio_deployment_design_v3.md)。本手册中的`HOST`、`USER`、`PORT`和`/DATA_ROOT`都是占位符，不是可直接执行的真实连接信息。实际SSH参数保存在被Git忽略的`config/deployment.local.json`；远端路径与恢复清单保存在私人部署记录。

## 1. 日常打开

双击本机桌面的“VibeNovel 远程工作台”快捷方式即可连接。也可在本机项目根目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/studio_remote.ps1
```

启动器读取已有配置，通过本机公钥建立SSH隧道并打开默认浏览器。若只连接、不自动打开浏览器：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/studio_remote.ps1 -NoBrowser
```

连接成功后，浏览器访问`http://127.0.0.1:18000/`。关闭浏览器不停止服务器或已发送的模型任务；网络断开后重新运行启动器，先查看原任务状态，不重复点生成或重发付费请求。启动器只管理此次SSH隧道，不安装服务、不生成正文、不调用模型，也不停止未知占用进程。

此地址需本机隧道保持连接。其他电脑不能直接借用本机18000入口；需先获得合法SSH公钥访问，并在该设备建立自己的回环隧道。

## 2. 配置位置与入口区别

| 文件或入口 | 用途 |
| --- | --- |
| `config/deployment.example.json` | 无真实凭据的六字段连接示例 |
| `config/deployment.local.json` | 本机实际SSH主机、端口、用户和隧道端口；不入Git，不填写API key或私钥正文 |
| `tools/studio_remote.ps1` | Windows启动器；已有隧道须同时匹配配置、进程身份、监听归属及Studio响应才复用 |
| `http://127.0.0.1:18000/` | 经SSH隧道访问远端正式工作区 |
| `http://127.0.0.1:8000/` | 本机旧日常入口；正式切换后停止本机服务，避免误写旧副本 |
| `http://127.0.0.1:47328/` | 独立真实API验收工作区，保留自己的预算和测试作品，不作为正式创作入口 |

模型API配置已获作者单独迁移授权，仅保存在远端私人工作区的`config/api.local.json`、`config/models.local.json`等实际存在的本地配置；不输出内容，不进入发行包、Git或前端静态目录。根目录及凭据父目录限制访问，凭据文件按0600限制读取。GitHub令牌没有迁移，也不是运行Studio的必要条件。

## 3. 查看或重启常驻服务

先用实际连接参数进入服务器：

```powershell
ssh -p PORT -o BatchMode=yes -o StrictHostKeyChecking=yes USER@HOST
```

随后在服务器执行：

```sh
systemctl --user status vibenovel-studio --no-pager
systemctl --user is-enabled vibenovel-studio
loginctl show-user "$USER" -p Linger
```

当前配置应为服务启用且运行、`Linger=yes`。需要维护性重启时，先在Studio中核对所有运行中的任务及费用状态，确认没有需要保留连接的操作，再执行：

```sh
systemctl --user restart vibenovel-studio
systemctl --user status vibenovel-studio --no-pager
```

需要停机维护时使用`systemctl --user stop vibenovel-studio`，维护完成使用`systemctl --user start vibenovel-studio`。单工作区只启一个后端进程，不另外运行一份命令行服务或多worker。进程重启只恢复HTTP服务；已发送、未知费用或失败的模型请求不自动重放。

诊断日志可在服务器本地查看：

```sh
journalctl --user-unit=vibenovel-studio -n 100 --no-pager
```

分享诊断时只摘取必要错误，先去除模型凭据、私人小说和研究原文。不要把配置文件全文或整个工作区当作问题报告上传。

## 4. 无法访问时

| 现象 | 处理 |
| --- | --- |
| 未找到部署配置 | 对照示例检查本机`config/deployment.local.json`；保留已填写的实际配置，不把真实连接信息提交Git |
| 公钥或主机密钥检查失败 | 检查网络、公钥访问和已有可信主机记录；不要关闭严格主机密钥检查或把私钥粘贴到配置中 |
| 本机18000已被占用 | 核对占用者；启动器不会结束未知进程。确需换端口时仅修改本机`local_port`并使用新地址 |
| 隧道已确认、Studio响应无效 | 在SSH中检查服务状态和日志；保留已知隧道，修复服务后重试，不重新发送生成任务 |
| 页面断线，但先前模型任务可能已发送 | 重新连接后查看该任务及原响应；未知费用保留原预留，不因超时假定未扣费 |
| 看到旧作品或旧界面 | 核对浏览器是18000正式入口还是8000本机/47328验收入口，再核对发行版本；不要直接复制覆盖当前数据 |

SSH连接不受本机浏览器关闭影响。服务器重启后的可用性仍依赖主机、磁盘挂载、网络及用户管理器正常；`Linger=yes`解决退出会话后的用户服务常驻，不保证主机永不宕机。本次实际验证了服务重启与恢复，没有重启共享服务器整机。

## 5. 数据主副本与备份

远端现为唯一可写主副本。本机原8000服务已停止，原工作区作为迁移前完整备份保留；该目录没有设置文件系统只读，请勿重新启动本机旧服务继续写作，也不要在两边创作后直接覆盖合并。

本次迁移快照为28,936个文件（原始1,344,762,490字节，压缩包472,650,675字节），远端恢复后全部逐文件SHA256一致；正式服务末次重启后314个关键文件仍一致，覆盖正式内容、研究与效果结果、原费用记录和模型配置。Linux BGE已实际完成`1×512`维归一化向量推理，18000浏览器入口已显示3部正式作品及16本参考书。部署验证未发送模型API请求；保存的API配置已迁移不等于已经验证远端付费调用。

“精读与结构图”的4个历史工程已在远端界面核对：跨书比较1/1与《活着》主动补读1/1完成，《活着》连续精读保持中断6/14、禁止自动重放，《鬼吹灯》连续精读完成38/38；未启动或续跑任务。这表示历史记录已恢复，不代表全部参考书均已完成全书研究。隧道不在时重新运行启动器的重建与页面恢复也已实际验证。

完整数据备份必须包含：

- 全部`novels/`：正式章、草稿、记忆、计划、导入原件、历史、提案、`.runtime/`、模型响应与作品预算。
- 全部私人`library/`及作品内资料：原书、解析旧新版、父子映射、研究批次与检查点、方法来源、独立研究账户及费用记录。
- 工作区所需配置与模板。含API配置的备份按凭据同等保护；GitHub令牌不属于部署备份范围。
- 程序提交、前端构建与发行校验信息；BGE模型版本和索引来源。可重建缓存不能替代原件、已付费研究或账本。

制作或恢复快照前，先停止新任务并核对在途请求，再停服务或使用一致的数据库备份方式。SQLite不能只复制写入中的主文件而遗漏WAL/journal。备份保存到数据盘私人目录，记录逐文件数量、大小、SHA256，并实际回读账本及恢复清单；仅文件压缩成功不等于恢复验收通过。

历史未知费用及`reserved`预留迁移时原样保留。它们不是可自动退款或清零的余额，切换服务器也不意味着允许重复研究。独立47328验收总账不和正式作品预算混合。

## 6. 升级和回退

升级前完成一致备份；代码与`studio/dist`使用同一提交，本机构建后传入独立发行目录。服务器独立Python环境不替换系统Python，也不依赖服务器旧Node构建前端。先用隔离样例验证新版本，再停止正式服务、切换成对的代码和前端并启动。

回退前先保存切换后新增的正文、任务、模型原响应和所有费用证据。若已发送过新请求，不能恢复旧账本使这些费用记录消失；须保留新记录后选择兼容的代码/数据恢复方案。任何备用副本均不得自动执行旧任务。

固定域名是后续独立阶段，需要真正的身份认证、受保护的读写入口、CSRF/Origin/Host边界、HTTPS和防火墙验收。当前通过SSH隧道使用，无需更改DNS或开放公网8000端口。

## 7. 校园网与公网访问操作边界

本节用于决定下一步入口，不是已执行的开放端口命令。当前可用入口仍是本机SSH隧道`http://127.0.0.1:18000/`；远端Studio仍只监听`127.0.0.1:8000`。没有完成应用远程模式、登录认证和TLS验收前，不得把8000绑定到`0.0.0.0`，也不得把18000转发到服务器网卡。

### 7.1 只给少数协作者使用

为每位协作者建立独立公钥和受限SSH账户，再在其设备建立自己的回环隧道。不要共享作者私钥、`deployment.local.json`或API配置。协作者访问的是本机回环地址，服务器端口和Studio代码无需改变。隧道断开后，重新连接并查看已有任务状态，不能因为页面超时重复发送生成请求。

### 7.2 让校园网用户访问

先向网络管理员取得服务器校园网IP、允许的校园CIDR、入站端口和校内DNS/证书方案，并记录在私人部署清单。校园网连通性只能证明网络可达，不能代替登录认证。

正式校园入口必须满足以下顺序：

1. Studio启用显式`campus`远程模式，配置可信反向代理地址和允许的HTTPS Origin；实现登录、会话注销/失效、角色权限、CSRF、请求体限制和付费POST幂等保护。
2. Caddy/Nginx只监听校园网网卡的`443`，上游连接`127.0.0.1:8000`。代理不重试生成POST，不公开8000、18000或管理端口。
3. 服务器防火墙仅允许校园CIDR访问`443`，SSH仅允许管理网段和密钥；先用隔离工作区在两台非作者设备验证登录、只读/写权限、断线恢复、任务状态和日志脱敏。
4. 验收通过后才把入口指向正式工作区。多人默认使用隔离只读或协作工作区，正式作品和研究账本仅授予明确角色。

校园阶段可以先用内网IP做TCP/HTTPS连通性测试，不必购买公网域名。稳定使用应配置校内DNS和有效内部证书；不要在HTTP页面中填写API key或登录密码。域名只是入口和证书标识，不提供权限控制。

### 7.3 让校外用户访问

推荐先采用“云端网关、数据留在校园”的路线：

```text
校外浏览器 --HTTPS--> 阿里云ECS/云网关 --WireGuard出站隧道--> 校园侧代理 --> 127.0.0.1:8000
```

实施顺序如下：

1. 购买云主机和最终域名，配置DNS、证书和仅`443`入站的安全组；公网IP仅用于临时测试，不作为长期入口。
2. 云端只运行TLS、登录、限流和反向代理；与校园侧建立密钥轮换、单向允许列表和断线监控的WireGuard隧道，避免校园防火墙要求公网入站。
3. 校园侧仍保持Studio回环监听和应用权限校验，禁止公网直达8000/18000；云代理不得自动重试付费POST。
4. 在隔离工作区验证登录、权限、CSRF/Origin/Host、断线恢复、重启后任务不重放、备份恢复和费用日志，再考虑正式工作区。

若选择将Studio整体迁移到ECS，必须迁移完整作品、私人资料、研究账本、索引、备份和模型配置，并维持唯一可写副本；校园副本应转只读。公网ECS需要独立补丁、监控、备份、恢复演练和费用上限。中国大陆地域还需评估ICP备案；香港/境外地域需评估跨境网络、学校政策和数据路径。

### 7.4 每次开放前的停止检查

- 未确认服务器校园网IP/CIDR、上游ACL和证书方案时，停止在网络层改动。
- 未完成应用登录、权限和CSRF/Origin/Host校验时，停止配置反向代理。
- 未完成隔离工作区验收和完整备份时，停止切换正式工作区。
- 未记录监听、防火墙、代理、证书、备份和费用证据时，停止对外宣布“已部署”。

任何阶段失败都回退到已验证的SSH隧道，不关闭现有回环校验，不清除历史账本，不重放未确定结果的模型请求。
