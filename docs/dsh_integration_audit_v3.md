# dsh-novel-writer 借鉴落地审计

日期：2026-10-19。审计基线：VibeNovel `3.0.0a4`，本地提交 `b69ef0a880d55c15fa7429219d119fcc5e68f073`。本轮是只读审计与方案设计；下面的问题均未在本轮修复，不代表作者已批准后续实施。

## 结论

四个主要模块已经接入真实后端、任务与界面，属于原生能力借鉴，不是安装了完整 dsh-novel-writer。最扎实的部分是作者固定样章、报告版本绑定、审批边界与候选输出；尚不能把它评价成完整的长篇自动审稿系统。

前次“本地检索已完成”应精确理解为**字面词项检索已完成**。插件中的本地 embedding 语义检索、专有词表、人物缺席/伏笔跨度看板、逐项自动复测与完整风格对照均没有完整落地。部分已有明确延期，不能将这些延期能力与已实现模块混称为完成。

## 可复现问题

P2表示正常功能/证据链缺陷，建议进入下一次维护；P3表示较低优先级的输入一致性与效率问题。本轮未发现已复现的正式内容越权写入，但这不等于全面安全保证。

### A1 · P2：记忆文件名版本号被误当章号

位置：`src/vibenovel/core/briefs.py:194`–`199`，当前取文件名**最后一串数字**作为章号。

复现：临时作品通过正式审批分别保存第2、4章正文、第3章计划，以及 `memory/events/ch004_v1.md`，内容注明第4章才发生的事件。第3章写前包会正确省略第4章正文，却把事件文件按最后的`1`视为第1章资料，实际API提示词也含该未来事件。

影响：角色知识与过去状态可能受未来信息污染。普通的来源hash和作者批准不能纠正时点解释错误。

建议验收：使用明确的结构化时点或严格章号规则；版本号、日期和无法确定时点的文件不得靠最后一组数字猜测。覆盖`ch004_v1.md`、`ch004_2026.md`、日期文件、无章号汇总和回写历史章。过渡期对歧义文件列为未检查/待确认。

### A2 · P2：低优先级提示挤掉高优先级重合警告

位置：`src/vibenovel/core/analysis.py:363`–`396`。

复现：草稿前100行均含套话，后面附上一段与正式章节相同、超过40个标准化字符的独立段落。报告100项全部是`canned_phrase`，没有`literal_overlap`警告；去掉套话行后，同一段落可正常产生重合警告。

报告已有`issue_limit_reached=true`，不能说完全没有截断提示；缺陷是先生成的info耗尽额度后，后生成的warning没有保留位置，覆盖记录也未说明各规则丢掉多少项。

建议验收：有界候选排序或每规则保留额度，高价值警告优先；记录各规则发现数/返回数/截断数，并保持内存上限。加入100条低优先级提示与1条高优先级重合并存的样本。

### A3 · P2：重复提示缺少逐项对应历史证据

位置：后端`src/vibenovel/core/analysis.py:385`–`396`；前端`studio/src/api.ts:170`–`180`、`studio/src/AnalysisWorkspace.tsx:210`。

后端已生成`related`，带历史文件、hash、行号和原句；前端类型与渲染没有使用。作者只能看到待审原句与“相同段落”提示，不能直接对照哪一章的哪段话。全局扫描文件清单不能代替逐项证据。

建议验收：每条重合提示展示两侧原句、精确来源和版本；来源变更后明确标记失效，支持打开对应历史快照或重新分析。

### A4 · P2：旧检索结果跳到新正文的旧行号

位置：`studio/src/AnalysisWorkspace.tsx:164`–`180`、`:225`；`studio/src/App.tsx:361`–`393`。

复现路径：查询正式章→通过另一窗口或审批修改该章→刷新写作检查状态。旧引文与hash继续显示，来源按钮读取当前正文，再按旧行号定位，没有失效提示。审稿报告已有类似保护，检索结果漏了这一层。

建议验收：比较结果hash与当前文稿hash；失效时重搜或打开匹配版本。旧行号不得无提示地解释为当前行号。跨窗口更新和版本回退均需覆盖。

### A5 · P3：实际输入重复附正文，与写前包摘录范围不一致

位置：`src/vibenovel/studio/jobs.py:482`–`485`；对应`src/vibenovel/core/briefs.py:175`–`177`。

选择已纳入写前包的上一章作为起草来源，compact包只包含结尾摘录，但最终提示词先全文附所选文档，再附写前包。复现前章17,523字符：包12,954字符、不含开头；最终提示词30,856字符、包含开头，末尾承接文字出现两次。

这是输入去重与预览一致性问题：60,000字符限制当前仅针对brief本体，最终提示词还有220,000字符上限，不能说不存在全局上限。

建议验收：统一所选来源与写前包装配，显示实际发送范围与总预算；包内已有资料按版本与区间去重，额外作者输入单独列出。
