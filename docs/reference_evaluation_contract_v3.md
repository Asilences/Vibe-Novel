# 方法效果与文学练习评阅（a12）

本模块完成「研究方法是否有助于新场景写作」的可重复流程，不把一次AI评分当作文学效果结论。练习和评价全部位于私人`library/evaluations/`，不写`chapters/`、`memory/`、已批准计划或固定文风样章，不自动采用方法。

## 三条件与两种评价

作者选择一个已有成功阅读结果的研究、1–6个研究方法索引、全新练习简报，以及本评测美元预算。输入固定研究方法origin、研究检查点、原书版本和授权epoch；方法可以是未采用候选，测试方法不授予正式创作使用权限。

同一简报产生三个独立新场景：

1. 无参考：只给练习简报和共同写作要求。
2. 简要方法概述：另给方法主题和不带出处的简要步骤概述。
3. 结构方法与证据：另给方法步骤、适用局限和固定版本原文短引文。

输出各为80–12000字符的独立原创新练习，建议600–1000中文字符。提示禁止复制独特语句、改名复现原人物或原剧情；如果与实际提供的来源引文出现至少24字符连续重合，则保留响应待修，不把它当原创效果样本。该筛查只覆盖实际提供的短引文，不代表完成全书查重或证明原创。

三个样本随机分配`sample-A/B/C`，再经一次全新请求做匿名AI评阅。评阅输入仅有简报和三个匿名正文，不提供生成条件、方法名或对应关系。默认仍使用同一冻结模型，所谓独立是**独立请求**，并非独立模型。输出对全部样本的因果、人物、节奏、表达、连贯五维0–10整数分、优缺点、来自对应样本的逐字证据、完整排序和局限。

作者可独立阅读三个匿名样本，保存偏好分、排序与阅读感受。作者评价与AI评价分别存储；首次作者评价后才由页面揭示条件映射并展示AI评阅，后续记录标为`AUTHOR_REVIEW_AFTER_REVEAL`，不冒充新的盲评。服务端保存AI评阅可能已存在的提示，因此不声称实现研究级双盲。

## 预算、冻结与耐久执行

三次生成+一次AI评阅，共4次模型请求，全部通过现有`ResearchGateway`，与精读、重读、跨书比较和其他评测共享独立研究账户总费用上限。每份评测另有自身美元上限，不能靠拆工程绕过账户总额。

预览冻结精确的三个生成prompt、方法origin、模型快照身份、研究账户配置与价格hash、每次输出上限、评审模板版本和四请求保守费用。评审正文只有样本齐备后才存在，因此预览使用三个最大允许样本计算输入上界；真正评审prompt和精确报价在发送前另行持久化，不宣称预览已知道未来样本文字。实际报价超过冻结上界或模型/价格/账户配置变化时拒绝新发送。

保存得到`prepared`工程，不付费。显式`start`后顺序执行；暂停保留当前已发请求，完成落账后停止后续节点；取消保留既有费用与原响应。每个节点先保存请求和确定幂等键，再经共享网关发送。失败或未知节点不能通过重启、继续、换提交键自动重放；原响应可由作者离线修复并保留修复理由和独立结果版本。没有原响应的未知发送必须先人工核对账户，系统不会猜测未计费。

研究来源在启动、每次发送及迟到结果发布前重验；授权收紧再恢复不复活旧origin。结果内容hash、结果路径所属工程/节点、计划hash、匿名分配、人工评价hash均校验。状态使用revision比较更新；执行器持跨进程任务锁。第二个server或pilot进程构造manager时，仅在能取得任务锁、确认没有live runner后标记遗留`interrupted`，不会打断另一个仍运行的试点。

## 存储与API

每个评测位于`library/evaluations/<evaluation_id>/`：

- `manifest.json`：固定计划、方法origin与进度、匿名条件分配、人工记录指针。
- `requests/<node>.json`、`responses/<node>.json`：每次实际发送的完整prompt/报价/确定键，以及原始响应/usage。
- `results/<node>[-<repair-version>].json`：已校验候选结果；修复不覆盖旧版。
- `repairs/<version>.json`：离线修复正文、原响应hash、理由与作者编辑性质。
- `human/<version>.json`：独立作者偏好及样本指纹；AI评分不写入这份记录。

每份记录最多8MiB，原始响应JSON文本有界解析，不吞掉重复字段或非有限数。私人目录不进Git。备份须保留评测、来源研究、书籍原件/各edition与方法origin，并保留共享研究账户完整费用账本/原响应；不能只备三个练习正文。

HTTP：

- `GET/POST /api/reference-evaluations`
- `POST /api/reference-evaluations/preview`
- `GET /api/reference-evaluations/{id}`
- `POST /api/reference-evaluations/{id}/start|pause|cancel`
- `GET /api/reference-evaluations/{id}/nodes/{node}/response`
- `POST /api/reference-evaluations/{id}/nodes/{node}/repair`
- `POST /api/reference-evaluations/{id}/human-review`

请求不接受API key或任意路径，继承Studio的CSRF、Host/Origin和普通请求体限制。研究账户密钥仍只由既有provider在本机解析，不复制到评测记录。

## 验证与结论边界

新增10项离线核心/真实StudyOrigin/HTTP测试通过，覆盖：prepared不调用、三条件内容分离、四请求完成、匿名评审不含条件标签、作者/AI评价分开、确切样本证据、来源在发送中撤回、预算上限和计划篡改、离线修复不重发、遗留未知请求阻断、第二进程不打断live runner、实际原文授权失效、CSRF与严格字段。前端TypeScript检查通过。

真实试点的调用数、费用与文学观察由本轮主验收文档记录；本模块单元测试使用合成书和虚构响应，没有产生API费用。单场景/单种子/同模型评分存在抽样、位置和自评偏差，不能证明条件间有统计显著差异，不能据此声称完整吸收、训练完成或方法普遍有效。
