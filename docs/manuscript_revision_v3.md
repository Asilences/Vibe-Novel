# 已有小说分析与修订

2026-10-19，3.0.0a6。作者在DSH审计修复后追加授权，为已写好的小说提供审计与修改入口。此阶段不实施多模型路由或多文件正式定稿。

## 编辑目标与决策

流程为：保真导入或选择已保存稿件 → 分章预览与作者校正 → 建立独立修订副本 → 选择章节/选区 → 本地规则线索或API证据审稿 → 表达编辑候选 → 章节差异 → 作者接受到副本 → 复查与独立导出。

减少套话、重复解释、模板表达，增强具体动作/感知、自然对话和作者文风，是可选择的编辑方向。“降AI味”不是可靠的AI作者识别，不输出生成概率或检测分数，也不承诺通过外部检测。深入编辑只扩大表达修改幅度，不授予改变情节、事实、人物知识和结局的权限。

本地检查按全文章节执行，即使API选区开关开启，也会在按钮和报告中明确该范围。API证据审稿和改写按整章或精确选区执行；结果只是作者待核对的候选意见。未提供的上下文标为未查到，不将有限输入描述为整书一致性检查。

## 原稿与修订存储

- 导入沿用不可变bundle。已有普通Markdown来源也可建立会话；其hash变化后原会话会失效，副本保留，需核对并新建会话。
- 分章以原文行起点建立精确、连续、无遗漏的字符区间。中文数字/阿拉伯数字章回和英文Chapter标题可被建议识别；特殊标题由作者校正。首章前内容独立保留，正文提到“第一章讲过”不应自动切章。
- 清单为 `reviews/manuscript-<id>.json`，工作副本为 `drafts/manuscript-<id>/chNNN.md`。清单记录原来源hash、字符/行号区间、顺序与初始副本hash。清单最后发布，准备失败不呈现完整会话，可能保留可恢复的孤立草稿。
- 清单必须保持创建版本；编辑或回退清单会被拒绝。副本允许在现有编辑器中手工编辑，保留版本历史。它不成为正式章节或正式记忆。
- 导出只连接当前会话的工作副本，不混入其他草稿/正式章；在修改稿末尾缺换行时补必要分章分隔。未修改且具有原始分隔的稿件逐字往返一致。

## 分析范围

新增批次本地分析只使用本会话显式副本语料，不自动附入正式作品历史或其他草稿。单批最多20目标、50万目标字符，对照最多80份/8MiB；每份报告仍受100条优先线索上限约束。返回请求数、完成数、对照数、来源hash与遗漏原因。逐批按钮需要作者明确继续，不自动发起付费调用。

跨章段落重合展示两侧原句和版本；可能是引用、前情或有意呼应，不能直接判定剧情语义重复。报告的 `explicit_corpus` 保存检查域；复查仍使用相同路径集合的当前版本，缺失、变化、截断不会被自动算成问题已解决。回顾性审查可以对照后续章，这不等于允许当前章人物拥有未来知识。

API编辑任务显式携带 `editorial` 和可选 `selection`。只提供当前正文范围、作者规则、有效固定样章统计、词表与明确锚段；不隐式读取最近正式章/记忆。普通旧审稿任务保留既有连续性上下文行为。所有附入参照有版本绑定，样章/锚段只约束表达，不能增加情节事实。

## 选区与接受

`selection` 为Python Unicode字符半开区间 `[start_char,end_char)`，绑定完整基文hash。浏览器textarea的索引按UTF-16且会规范换行，需映射回原始CRLF/单CR及Unicode码点，避免Windows稿件偏移。任务只要求模型输出选区替换正文；后端以原文前缀、替换和后缀拼成独立完整章候选，保留区间外UTF-8字节。重启恢复使用已拼好的完整候选，不二次拼接。

接受操作验证当前会话、章节路径、基文hash、成功API改写任务、候选path/hash/最新版本ID、全部输入参照与运行配置；候选被编辑再回退也不能冒充原始模型版本。通过后只更新一个修订副本并记录接受候选来源，保留原稿与旧版。正式正文/记忆不参与此事务。

## 验收与限制

测试只使用临时作品与离线假模型。最终本地/云端数字与浏览器记录见 `implementation_plan_v3.md`。实际付费服务商对不同模型的编辑质量仍需作者试用评估，不以协议回归代替文学验收。

仍未提供：可靠AI检测、自动人物知情/OOC判定、自动语义重复裁定、任意长度全书一次输入、导入稿自动定稿、正式正文/记忆多文件事务。作者应逐条核对意见，接受前审阅差异。
