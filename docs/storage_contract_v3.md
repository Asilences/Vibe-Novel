# M0 存储与输入契约

`schema_version: 1` 为 M0 数据格式版本，软件版本单独管理。未知版本拒绝读取；不猜测迁移。源文件是权威，完整性 hash 用于检出变化，不能证明作者批准或抵抗具备同权限的恶意修改。

## 作品

`novels/<id>/project.json` 保存 id、title、genre、创建时间和 schema_version。ID 为小写 ASCII slug，不含路径分隔符，拒绝 Windows 保留设备名。作品内相对路径统一使用 `/`，跨平台均拒绝反斜线、绝对/UNC 路径、Windows 别名及无效 Unicode。所有作品内路径先检查其组成和链接/junction，避免静态路径逃逸；这不是抵抗同 OS 权限并发换链攻击的安全沙箱。

每部作品含 `imports/original`、`bible`、`outlines/source`、`outlines/proposals`、`outlines/approved`、`drafts`、`chapters`、`memory/{events,states,summaries,threads}`、`approvals`、`reviews`、`exports`、`.runtime`。创建在同层临时目录完成后发布；不覆盖已存在目录。根目录旧小说资料不纳入 v3 查询。

正式内容指纹覆盖 `project.json` 和 `bible/`、`outlines/approved/`、`chapters/`、`memory/` 下文件的相对路径与原字节 SHA256。路径/删除/手改会改变指纹；不包含导入、候选、草稿、导出、运行缓存。它是当前内容的 fingerprint，历史回退到相同内容会得到同值。Studio 的单调 revision、历史快照与审批决定另行记录；细粒度锁定字段仍待实现。

## 原件导入

仅 MD/TXT。默认严格 UTF-8，识别 UTF-8/UTF-16 BOM；旧编码需明确指定，不猜测、不用 replacement 丢字。读取有字节上限。原件内容 hash 为导入 ID，目录 `imports/original/<sha256>/` 中三个文件共同发布：`original.<ext>`、`extracted.md`、`metadata.json`。

metadata 保存作品 ID、首次导入文件名、字节 hash、抽取 hash、编码、格式、抽取器版本、UTC 时间和行/字符来源区间；来源身份 SOURCE、信任 untrusted、canonical=false。抽取文本仅供检索/分析，不能作为项目命令执行。字符区间为解码后 Unicode 字符位置，行号从 1 起，不能直接套用于原始字节。重复内容复用首次来源记录，不覆盖；改变解码方式必须先明确处理已有导入，不静默重解释。原件默认上限 10 MiB、可配置至 100 MiB；来源最多 20,000 段、metadata 上限 8 MiB，超限时提前拒绝并提示分文件导入，不部分丢弃出处。

先在同一文件系统的临时目录准备完整 bundle，再 rename 发布。M0 的单目录发布不等于 M2 的跨文件定稿事务。校验器重算 hash、校验文件布局及来源区间；不是语义/文学审查。原件采用应用层不可改写规则和 hash 检查，不声称 Windows ACL/WORM 强制只读。暂存残留不纳入导入清单，异常残留由 verify 提示。

## 导出

只读 `chapters/chNNN.md`（至少三位、正整数），编号按数值排序；相同数字的不同补零命名报错，所选范围缺章报错。可选择起止章节。`verify` 检查从第 1 章起是否连续、正式章节是否为非空 UTF-8；未定稿导致缺号也会提示，作者可明确导出已有连续范围。目标仅是 `exports/` 内单个 Markdown 文件名，默认不覆盖；导出不创建正式章节或记忆，不包含草稿。按卷导出需未来的卷归属 Schema。

## Studio alpha 补充（3.0.0a2）

`approvals/.studio/state.json` 是版本化权威记录，保存单调 revision、历史快照、正式指纹、提案和决定（上限64 MiB）。`approvals/.studio/journal.json` 是未完成单文件事务的持久化意图；不得当缓存删除。核心获取 `.runtime/studio.lock` 的线程/进程排他锁后先恢复 journal，再读取或写入。正常短操作等待锁最多2秒，超时返回409。不能确定的漂移保留 journal 并停止写入。

单文件事务先写 journal，再发布目标文件，再发布新状态，最后删除 journal。恢复核对前后状态与目标精确哈希；批准仅消费一次。此协议不构成 chapters+多份memory 的批量原子定稿。正式 revision 与当前指纹分开：通过核心观察到的回退仍推进 revision；两次观察间完全恢复原状的外部变化无法检测。

候选/审稿直接保存绑定 expected_hash，恢复作为新版本。生成任务发布还绑定 context_sources、fingerprint、canonical_revision，在同一核心锁内检查；不将 API 输出自动升级为正式事实。已批准章计划须有 applied 提案及匹配 after_hash。

任务状态保存于 `.runtime/jobs/<id>.json`，不是正式小说事实；关闭浏览器不会删除，备份作品时也应保留未完成任务。每工作区 `.runtime/studio-jobs.lock` 阻止第二任务服务重复调用。运行请求重启变为中断，排队/暂停状态恢复；旧Codex接力任务仅保留历史且禁止继续或重试；无自动付费重试。候选返回后先持久化精确发布意图，崩溃后核对候选及来源历史，已完整保存则恢复成功；未发布则由作者显式恢复；冲突文件不覆盖。

2026-10-21付费响应补充：新API任务的原始UTF-8响应单独原子保存于当前作品`.runtime/provider-responses/<jobid>.txt`，原文最多4MiB；任务JSON的`_provider_response`只保存固定相对路径、字节数、SHA256、用量、模型和停止原因，不再内嵌重复归档原文。候选发布意图或JSON修复内容仍按各自规则保存；原响应归档不替代来源/结构/审批校验。已有不同内容的同路径归档拒绝覆盖，不为修复存储而再发模型请求。

读取归档只接受任务ID派生的精确路径、同一作品身份、严格整数字节数、4MiB上限、UTF-8和SHA256全部匹配；不信任客户端路径或任务中伪造的已投影正文。缺失、损坏或跨作品归档不提供响应投影，不回退读取任意文件。失败API任务的完整有效响应只可标为“未成功发布”的只读归档，不能由此取得恢复、采用、正式审批或过期来源的继续使用权限；截断/空正文/异常停止原因及已报告用量仍分别保留，不冒充完整成功。

旧的小任务记录继续兼容内嵌原响应，不批量迁移。仅当旧任务JSON超过8MiB、且不超过16MiB时，启动读取可执行有界兼容去重：先严格读取并校验原任务及≤4MiB响应hash，将原响应写入上述固定归档；确认去重后的任务JSON≤8MiB后，把完整原JSON逐字节备份为`.runtime/provider-responses/<jobid>-legacy.json`，最后更新任务清单。已有不同备份、损坏响应、非兼容格式或去重后仍超限均拒绝，不覆盖原件、不清费用、不重发请求。此路径是保存证据的存储修复，不是候选重发布或重新付费。

完整作品备份须包含整个`.runtime/`，特别是`jobs/`清单、`provider-responses/`原响应及旧JSON备份、路由和预算账本；仅复制任务JSON或候选正文不构成完整备份。原响应含私人提示结果，默认不入Git，与其他作品运行资料同等管理；不保存API密钥。

未迁移单API模式的密钥由固定的 `config/api.local.json` 或后端进程环境提供，环境变量按字段优先。a7新增注册表后以本文末尾补充为准：新表存在时不再混入旧配置，每次调用核对冻结快照后才解析密钥。真实配置与备份排除Git，只有空凭据示例可上传。HTTP仅提供固定配置的脱敏读取和专用更新接口；已有密钥不回显，保存受同源/请求令牌和版本hash保护，任务中不保存凭据；无效配置只返回脱敏原因。任务上下文及恢复候选包含作品内容，仍应按本地作品资料管理；不应将 `.runtime/` 上传到公共仓库。UI不开放任意本机路径或运行命令。

## 创作规划补充（3.0.0a3）

规划候选是 `outlines/proposals/blueprint-<jobid>.json`，正式规划包固定为 `outlines/approved/blueprint.json`。顶层版本、作品ID、稳定记录ID、数组/文本大小、卷章范围、引用和逐行证据均受校验。运行时覆盖source_hashes；模型不能扩充未提供来源或自称AUTHOR_APPROVED。完整契约见 `blueprint_schema_v3.md`。

规划的主输入只接受导入extracted文本、来源大纲或独立候选。有限正式资料可以作为上下文核对，不把它们当作可任意重写的主输入；禁止提案目标依赖自己的旧文件版本。暂不支持将批准包自身作为生成新包的主来源，也不提供局部合并。

新提案可带 `dependencies` 与 `dependency_versions`，两者纳入提案hash；后者记录依赖的已观测历史/审批版本。创建、批准、应用及使用章计划时检查，保留旧记录hash兼容。整包批准不表示事件已发生；提取章计划另外创建单文件提案，依赖父包和来源。Studio内A→B→A不能使旧依赖批准复活；完全未观察到的外部回写仍在现有存储保证之外。

章节起草将有效父包中与本章相关的规划人物、知情边界、文风、伏笔及时间线作为带范围说明的上下文，绑定父包hash。不能以父包规划替代正式章节事实。规划生成的无效JSON可保留在任务repair_candidate供人工修正，不发布到候选文件；修复也必须通过相同来源与结构检查，不自动发起新付费请求。

未应用的已批准提案允许作者撤销批准，保留旧决定及审计事件；应用后的正式变更不能通过撤销按钮回滚，须重新创建提案。

## 写作检查与设置补充（3.0.0a4）

写前包不另存小说事实；分项来源、缺失与字符预算返回页面，任务保留来源hash与样章配置hash。报告保存于版本化 `reviews/analysis-<id>.json`，逐项状态变更通过同一锁和journal；正式内容、样章或被引用正文变化使旧报告失效，失效报告不可标已处理。固定样章存于 `.runtime/style-baseline.json`，包含作者明确选定的版本快照，不因源文变化自动换样本。

生成与分析发布支持固定运行依赖 `.runtime/style-baseline.json` 的hash（未配置为null），在文档写入同一锁内核对，不开放任意运行文件读取。历史检索只读本作品正式章节，返回原句/行号/hash及未扫描范围；字词分数不证明事实或情节相同。

`config/api.local.json` 的专用更新使用工作区锁、expected_hash和原子替换。密钥空输入保留、显式清除才删除；更换地址需新密钥或清除。读取只返回地址/模型/has_api_key及环境覆盖字段名，响应不含已保存密钥或片段。旧配置中的codex默认值兼容读取为api，不恢复旧执行器。


## DSH能力完善补充（3.0.0a5）

`.runtime/writing-toolkit.json` 保存作者明确登记的词表、别名、禁用/必用提示、人物检索名、伏笔关键词范围和文风要求；这些是检查偏好，不是正式设定或实际发生记忆。乐观保存绑定expected_hash，最大512KiB、每类200项。锚段最多5处，限本作品chapters/drafts，来源hash与行号、原句严格核对；过期不自动换样，也不作为角色知情或历史事件依据。全局词库不自动合并，可由作者显式复制JSON。

新分析报告schema_version=2，兼容读取旧schema1而不静默迁移。新增逐规则found/returned/truncated、实际文风比较样本子集和runtime_dependencies。排除目标本身后以余下固定快照比较；人工resolved只表示作者标记。verify保存当前新报告，逐项返回remaining/not_found/unchecked，旧报告与作者标记保持；检查域、依赖或截断不确定时不假报解决。

运行依赖仅允许 `.runtime/style-baseline.json` 与 `.runtime/writing-toolkit.json` 的非空子集，未配置hash为null，任务/报告发布在同一文档锁内核对。锚段另绑定实际来源hash。写前包统一所选来源及区间manifest；compact/full均不额外补回已附的全文。任务记录最终提示字符数与220000总预算，预览仅对应材料包，作者任务和通用规则的额外字符在任务预算中明确列出。

记忆过去时点只接受严格chNNN（可带版本/日期后缀），或JSON顶层chapter、Markdown frontmatter chapter整数。章号冲突、无时点、未来章记录列为遗漏；记录内部误写未来事实仍需作者复核。结构看板只统计正式章字面提及和章号差，不自动写入实际人物状态或已回收伏笔。

本地语义固定使用Xenova/bge-small-zh-v1.5转换版本 `75c43b069aac4d136ba6bc1122f995fedcfd2781`（原模型BAAI/bge-small-zh-v1.5，MIT）。安装显式执行，模型与分词器均校验固定SHA256；正常查询没有下载或模型API请求。可选ONNX推理在限时隔离子进程执行，只接收有界文本并返回512维归一化向量。模型目录 `.runtime-build/models/bge-small-zh-v1.5/` 及每作品 `.runtime/semantic-index.json` 都是可重建派生数据，不能代替Markdown/JSON权威。

语义缓存绑定模型版本和片段hash，只保存向量，不从缓存返回原句/路径；每次返回当前正式正文的精确hash/行号/列号/片段。缓存损坏则重建，推理缺项/失败明确报错，不暗中退化为字面模式。检索前后正式revision/fingerprint变化则拒绝结果；界面刷新比对来源版本后禁用旧行号跳转，打开文稿再核对expectedHash。仍不宣称检测两个观测之间完全恢复原状的外部修改。

诊断接口只输出受限枚举和固定计数、版本、相对章节路径；不序列化任务error/prompt、小说正文/书名/配置正文或任意自由文本。此报告可用于反馈；正文检索与检查报告仍属于私人作品资料。

## 已有小说修订补充（3.0.0a6）

修订会话清单为 `reviews/manuscript-<id>.json`，工作副本为 `drafts/manuscript-<id>/chNNN.md`。清单最后发布、创建版本保持不可变；记录完整来源hash和无遗漏的原文字符/行号分区。最多80段/8MiB，每段20万字符。来源漂移不覆盖副本，也不自动成为正式事实。准备失败可能留有版本化孤立草稿，不发布完成清单。

本地批次报告复用analysis schema2的可选 `explicit_corpus` path/hash列表，限定当前会话的工作副本；复查保留相同路径集合，来源缺失/检查遗漏不能推断旧问题已解决。单批最多20目标/50万目标字符、80份/8MiB对照，报告逐份保存，返回明确coverage。批次结束复核会话、全部来源和报告失效状态。

显式 `editorial`/`selection` 的审稿与改写任务保存 `editorial_context`，绑定词表/样章运行配置和原句锚段来源；不隐式加入正式历史。选区为原文Unicode字符半开区间，浏览器索引先映射回原文换行/码点。模型仅返回选区替换，后端拼成完整候选；区间外原始字节保留，恢复不二次拼接。普通旧审稿任务上下文保持兼容。

接受候选须匹配当前章节路径、基文hash、成功API改写任务、全部输入与运行依赖、候选hash及 `result_version_id`。候选编辑后回退仍被拒绝。单文件journal只写修订副本，记录 `accepted_candidate` 及旧版；不修改原件、正式正文或记忆。独立导出只使用清单内副本，必要时补分章换行。

## 显式多模型与持久预算补充（3.0.0a7）

工作区固定文件 `config/models.local.json` 保存 `schema_version: 1`、单调 `revision` 和 1–16 个独立模型配置，最大512KiB。每项含稳定ID、显示名称、HTTPS地址（本机HTTP须显式允许）、model ID、允许角色、声明的上下文/输出容量、每百万输入/输出Token的美元报价（未知为null），以及仅供后端读取的独立密钥。公开接口只返回 `has_api_key`/`available`，不返回密钥或片段；保存受工作区锁、expected_hash及原子替换保护。空密钥输入保留该ID原密钥，显式清除才删除；改变地址时须提交对应密钥或清除原密钥，不能借保留行为把旧密钥发送到新接口。未知字段、重复ID、过量配置及非有限价格拒绝。

注册表不存在时，兼容读取旧 `config/api.local.json` 和原有按字段覆盖的环境变量，合成为未迁移的 `default_api`；读取不会创建注册表或改写旧文件。作者在页面点击迁移后，才复制当时有效旧配置到新文件。新表存在后，各模型使用自己的本机配置，不再混入旧单模型环境覆盖；旧文件原样保留。`models.example.json` 仅含空密钥、空model ID及待核实容量示例，不能证明模型可用、能力相同或报价有效。所有真实 `.local.json` 及备份排除Git。

每作品 `.runtime/model-routing.json` 保存schema、单调revision及作品策略。`planner/writer/reviewer/memory` 分别显式绑定一个主配置和最多两个有序备用；同一模型可担当多角色，角色必须在配置允许列表中。策略还保存共享调用次数、Token上限、可选美元上限和每节点最多1–3次技术尝试。保存校验配置身份及角色，不会自动发起验证请求。没有单独作品策略时，四个角色兼容绑定 `default_api`，默认一次调用、一百万Token、无美元上限及一次技术尝试；多节点流程须作者明确提高共享调用预算。

新任务在入队前保存无密钥 `route`：职责、策略revision/hash、模型注册表revision/hash、全部主备模型参数和目的地、保守输入Token估计、输出上限、预算组及尝试上限。估计使用完整提示UTF-8字节数加1024余量，输出另计；它是保守预算估计，不是服务商分词器实测值。每个允许目的地均须容纳输入和声明最大输出，不能通过截掉必需章计划绕过。请求带冻结的 `max_tokens`。策略后续修改不会重写旧route；注册表后续保存会推进revision，尚未发送的旧快照拒绝执行，观察到的A→B→A也不能复活。已发出的请求继续以其冻结模型产生候选，后续设置修改不把它改成新配置；正式来源与批准计划仍须在发布时核对。

调用时才在后端核对快照并解析对应密钥；密钥不进入route、attempt、上下文或日志。旧配置模式的地址/model/文件元数据变化使未发送快照失效；仅更换进程环境中的密钥、且接口和model不变时，允许按同一目的地轮换凭据，环境密钥内容不进入快照身份。旧模式对两个观测之间完全恢复元数据的外部回写不提供历史检测保证，正式迁移后应用保存由单调revision约束。每次技术尝试保留profile、模型、配置版本、用量及计费状态，未知费用不显示为零。认证、无效请求、来源漂移或连接超时不能通过换厂商绕过；仅已允许的429/部分5xx可以在剩余预算内尝试明确备用。

每作品 `.runtime/model-budget.json` 是schema1持久预算账本，最大4MiB、4096个流程组，每组最多32个尝试；不是可随意删除的可重建缓存。每次发送前，在作品线程/进程锁内按group_id预留一次调用、保守输入及最大输出Token、已知报价费用，再持久化调用意图。并发节点共享同一组，不能各自独立花完整余额；同一组不得在中途提高或更换预算，同一attempt_id不得重复预留。次数/Token/可选美元不足则拒绝发送；声明美元上限但价格未知时也拒绝。本机限制不能承诺厂商实际账单绝不超额，报价与额外计费仍由作者核对。

返回完整服务端用量后按报告的输入/输出重新计算；价格未知时金额继续为null。仅返回总Token时保留金额预留及不确定标志，缺失用量、超时、取消或发送结果不明时保留可能产生的费用预留；只有确认未发送才释放。`cost_usd` 是按作者所填报价和返回用量计算的估算，`reserved_cost_usd` 是尚占用的预算预留，两者都不是厂商账单。重启不会释放未确定预算或自动重放已开始的请求；普通显式重试沿原预算组，工作流节点禁止通用重试。账本损坏会停止调用，不静默清零。

工作流创建冻结策略/注册表身份，dispatch提交在入队前核对该身份，发送前再核对；竞争保存只会使旧流程失效，不能把后继换到新目的地。请求模型ID与服务端返回的 `model` 元数据分别记录，后者缺失或无效时保持null，不把请求ID当成服务端确认的实际身份。

路由配置、预算预留和模型评分均不增加小说写入权限。审稿与记忆抽取产物仍是带来源的候选；本阶段不实现正式正文与多份记忆的共同定稿事务。

## 从零开书与创作输入补充（3.0.0a8）

作品规则模块由固定白名单解析，阅读分类/标签不参与拼接路径。`general`新作品使用project schema2，现有四题材schema1仍原样读取与创建，不自动迁移。通用规则不等于具备所有题材专用检查。

`outlines/source/creative-brief.json`是schema1作者创作意图：词表版本、故事种子、阅读分类、共享词项ID及其来源/包含/避免/待接受/未定状态、主角与叙事、优势有无、开局因果、篇幅、文风和限制。专用接口严格校验全部字段，保存绑定hash和32位历史ID，复用文稿锁、历史和单文件journal。文件不存在时读取默认空简报但不写文件；空草稿可保存，生成须有故事种子。只有已选标签进入正向有效条件，避免项独立传入；AI待接受项不成为作者决定。通用文稿HTTP保存/恢复拒绝简报与选用记录两固定路径。

`generate_story_outline`是独立planner任务，预览不调用模型、不占用调用预算、不创建队列。提交绑定简报hash/history和预览的策略/注册表五字段身份，冻结词表、通用规则和题材规则。新任务必须带16–80位幂等键；同作品同键同请求和同配置返回原任务，异请求或配置拒绝。技术尝试共用冻结预算，默认一次；未知发送结果不自动重放，显式新请求仍可能额外计费。结果仅写`outlines/proposals/story-outline-<jobid>.md`，不生成正文和事实记忆。作者可编辑该候选并重新核对版本，原简报关联仍保留；简报失效需重新生成，不因恢复相同字节复活。

`reviews/creation-selection.json`是schema1受管选用记录，含作品、总纲path/hash/history、原简报hash/history、原任务ID、选用时间和持久`invalidated_at`。手写/导入纲可显式选用，不能伪造生成来源；生成纲由后端按固定候选文件名核对成功原任务，不能通过省略job字段绕过。选用是后续规划输入决定，不是正式事实批准。GET观察到失效后保留标记，恢复文件字节不自动恢复选用；重新选用需要当前来源与选用记录的精确双版本。

从生成纲展开`build_blueprint`须有仍有效且匹配当前总纲的显式选用。规划任务冻结总纲、简报、选用记录的hash/history，发送、迟到结果发布、崩溃恢复均复核；规划包保留这组来源，作者编辑JSON也不能删除原生成任务依赖而继续审批。创建规划提案时在写锁内再次核对历史，防止读取与提案保存之间A→B→A。已应用规划通过既有提案的依赖版本继续核对，不依赖候选文件名。

修改简报或改选后，旧规划的批准历史保留，相关规划可显示来源过期并阻止继续提取新章计划；不自动撤销批准记录，也不改已定稿正文或正式记忆。人物/世界、时间线/伏笔、文风导航只是同一规划包的投影，尚无独立按条资料编辑。当前不实现多文件共同定稿事务。

## 私人资料库与方法任务补充（3.0.0a9）

工作区 `library/` 是个人库；`novels/<novel_id>/library/` 是本书私有库，均默认Git忽略。新库不迁移根v2 references、不改既有import bundle布局、不写bible/chapters/memory。库不是可删除的缓存：备份须包含完整库目录；本书个人绑定依赖工作区个人库，目前不自动把它打包进单书导出。

schema1清单为 `.state/manifest.json`，含固定scope/owner、library_id、单调revision及source/entry/binding/collection/question/policy/bundle七类不可变版本索引。记录位于 `records/<kind>/<id>/<version_id>.json`，ID/版本为32位小写hex，hash为记录字节SHA256。每记录最多16MiB，清单8MiB/一万历史版本。准备不可变记录后，通过 `.state/journal.json` 最后发布一个库的清单；恢复仅完成本地发布，不再调用模型。没有跨库或小说正式内容的共同事务；符号链接/越界路径拒绝。

来源支持MD/TXT，原件与UTF-8抽取各不超过10MiB，显式编码及保真解码；原字节和UTF-8文本分别位于 `blobs/<sha256>`，同字节可复用blob而不丢不同书目记录。每来源版本固定原件hash、文本hash、解析器版本、书目信息、外发与撤回状态。引用固定scope/owner、source_id/source_version_id、Unicode码点半开区间和逐字quote，服务器计算行号；浏览器UTF-16与换行差异经原文映射，不用重复原句搜索猜位置。

entry有六类：literature/material/technique/style/term/method，收件状态inbox/ready/archived，核对状态unverified/checked/disputed/needs_evidence，作者/模型来源性质独立。研究问题可以保留冲突与未解决状态；“已核对”或“已采用”不会使内容成为故事事实。方法含purpose、steps、inputs、outputs、limitations、applies_to、counterexamples、checks。模型不能指定已有ID、作者身份、外发授权或采用；候选默认local/inbox/unverified。独立adopt接口记录作者采用；修改后需要重新采用，历史仍可回顾。

本书binding只显式固定个人entry版本与用途，读新版不静默换绑，不能引用另一作品私有库。库卡和来源的local/summary/excerpts分别表示仅本地、仅作者摘要、允许所选内容；source直接区间须excerpts。来源/条目保存的authorization_revision只在外发/撤回改变时推进；来源普通标题/笔记新版不废固定来源旧版本，个人binding仍固定所选entry版；本书entry直接任务依赖要求当前精确版本，编辑标题也会使其旧任务失效。收紧再恢复也不能复活旧任务/绑定。来源撤回与绑定收紧在选材、发送、迟到结果和恢复时再核对；跨库不存在分布式原子提交保证。

本书policy默认manual，另可recommend/auto，含类型、用途、专题、必选/排除ID、条目数与字符预算。recommend仅返回建议；auto只在授权用途内召回本书卡与已选个人绑定，不扫描别书或自动发整本来源。中文二元词项/精确匹配检索有400记录/8MiB上限并返回遗漏；这是有界本地检索，不是新增向量索引。自动选材上限为60000字符，普通写作装配另限24000且服从更小书级上限；可选项超限省略并记录，必选超限拒绝，零命中返回空资料但固定policy。整任务提示仍受220000字符上限。

任务资料snapshot schema1保存scope/owner/library_id、实际text、输入/遗漏manifest、真正实发的source_fragments、typed_deps、policy身份及hash。未发送的卡片出处不能冒充实发原句，仍保留有类型依赖和说明。预览不付费；有资料snapshot的提交必须携expected_library_hash，配置身份与资料hash不进入业务request而由submit专门校验。无库旧作品路径兼容；手动/推荐模式没有实际资料snapshot时不强加库hash。普通任务显式重试沿用原键/预算，不重启重放不明的付费请求。

`analyze_reference`与`extract_methods`为planner API任务，必须显式选择真实计费作品、资料scope、精确版本范围、用途及16–80位幂等键。个人来源也只读所选资料，不读取计费书正文。分析生成阅读地图/观察/方向/普通参考/缺口的technique卡；提炼必须绑定有效分析entry/version和原analyze job，以同范围、用途、计费书及预算组继续，可返回零方法，不凑数。模型JSON严格字段/有界文本；每条引用必须逐字匹配实际发送区间，原书案例与合成练习分开。

结果在job.result_library记录，不伪造文稿result_path。完整候选包先持久化待发布内容，再由库清单整包发布，按job ID、request_hash、snapshot_hash及expected_analysis幂等对账。提炼的分析身份在同库写锁内核对精确当前版本及非归档/撤回；journal恢复同验。失效待发布包保留rejected意图和候选对象，不暴露半套方法；已发布包完成记录失败时可对账，不重复生成或覆盖作者后来编辑。无来源、缺引用/结构错误保留待修，不自动重调。

总纲、纲要扩写、卷章规划、批准章计划起草、审稿和改写均可按本书策略补充资料；多模型工作流冻结初始库依赖，后继不能静默换资料。候选记忆仅抽冻结正文，不注入参考库事实。方法采用、词项分数、程序引用检查都不授予章计划批准、正式写入或文学效果结论。

普通文稿候选在发送与发布前核对资料依赖，但库与DocumentStore采用不同锁域，不构成跨存储原子事务。已发布文稿的库快照留在任务记录；后继工作流会重新校验，单文件提案/人工打开候选尚未统一接入库依赖检查。撤回资料不会自动删除或撤销已经发布的候选，不能据此宣称所有旧候选仍可作为当前有效资料继续使用。

## 参考书语料与批次研究补充（3.0.0a10）

参考书使用独立的`library/books/`，不将每个章节、块或分析节点变成a9普通资料卡，不改变旧库的10MiB来源、版本和扫描合同。目录schema1为`.state/catalog.json`，保存书籍、单调revision、外发/撤回授权版本与不可变edition指针；`.state/journal.json`最后发布目录，恢复先核对before/after指纹和版本文件。版本位于`<book_id>/editions/<edition_id>/`，原件在`originals/`，正文技术分册、分页章节、原文定位和`metadata.json`分别保存；导入先准备、核验版本，再登记目录，不发布半份版本。此本地事务不扩展为a9库、研究账本或小说正式内容的共同事务。

支持EPUB、TXT、MD：单原件上限128MiB，EPUB解包资源总量上限256MiB，规范正文每版本上限128MiB、最多20000章段；清单和章节页各最多8MiB。技术分册目标5MiB、硬上限8MiB，按实际UTF-8字节计算，优先保留章节边界，超长单章可跨块/分册但chapter_id不变。2GiB是**导入时参考语料配额**：发布前检查现有`library/books/`（排除暂存）加待入库原件、文本和定位等文件的体积；不是单原件上限、不是分册上限，也不构成后续分析结果永不超额的磁盘配额保证。容量不足明确拒绝，不通过切页静默丢弃正文。

原件以SHA256保留原始字节，TXT定位保留编码、字节/字符映射及坏字节缺口；EPUB定位关联包内资源、节点/锚点和可见文本区间，不用压缩包偏移冒充正文位置。解析版本为`reference-books-v3`；重解析形成新edition，不静默改写旧证据。原书卷、技术分册与未来叙事阶段是不同概念。附记保留分类，去空白正文相同只标`duplicate_of`候选，不自动删章或据章名去重。未解码范围标`incomplete/not_fully_decoded`；缺口和NUL等控制字符使章段`needs_review`，保留控制字符定位和计数，浏览器的“选本页完整正文”不包含这些章段。默认快照及批次预览拒绝含缺口/控制字符的范围；底层有界部分快照须显式`allow_partial`并保留缺口，当前网页与批次接口不借此绕过门禁。解析覆盖、未读范围、归档校验与发行版本完整性分别记录。

精确`book-evidence`固定book_id、edition_id、parser_version、chapter_id、Unicode码点半开区间、全章hash、range_hash及实际quote。模型快照及完整性核验重验原件指纹，目录/原文读取核对派生版本、块和定位指纹；模型引用必须逐字匹配本节点实际发送范围，不能凭书名、其他版本或未发送的章段补证。a10阶段检索为本地全文词项匹配，返回扫描覆盖及结果截断说明；当时未新增语义向量索引，当前四层混合检索见a12补充。解析、翻页、保存、核验和词项检索均不调用模型，资料中的指令不获得执行权限。

新书默认`local`，只有作者明确保存`excerpts`且未撤回，才可预览/创建分析；外发或撤回变化推进`authorization_revision`，A→B→A不复活旧授权。参考书分析必须显式指定真实计费作品、章段选择、用途、每节点输出上限及大于零的整批美元预算。计费作品只提供模型策略与既有BudgetLedger，不读取该作品正文或设定。所有节点的模型配置、价格和来源范围冻结；缺输入/输出报价、总预算不足或单节点超过作品预算即拒绝，不将未知费用按零估算。空chapter_ids明确表示全书全部章段（包括附属文本/重复候选），不偷换为已筛选正文；有异常会拒绝，可由作者选择无异常范围。

批次持久记录为`<book_id>/batches/<batch_id>.json`，每份最多8MiB；预览计入每节点1800字节进度预留和1MiB当前响应预留，超限明确要求缩小范围，不截断工程。`expected_preview`冻结整份预览hash，同一幂等键同请求返回原工程，异请求拒绝。创建状态为`prepared`，不发送模型；显式`start`后才运行。章节节点最多50000字符，优先按自然段切分；阶段/全书归并节点每组最多4个前置节点，递归至唯一根。预览费用上界包括全部章段与归并节点，父工程保守累计预留费用，节点另受所选作品共享账本限制；不能借拆节点绕过总预算。

模型单响应最多保留1MiB，标准候选JSON上限12000字符、单条引文上限240字符；无效响应保留待核，不自动再次付费。结构、表达、线索和方法均为有精确引文的候选JSON，逐节点独立保存于`editions/<edition_id>/analyses/<batch_id>/<node_id>.json`并固定hash。归并输入保留前置候选及精确证据，按节点有界输入处理；超限失败并保留已有结果，不静默舍弃字段，也不自动再次付费。节点详情按需读取完整候选，批次节点分页（默认50），预览展示前50及真实总数；这不是只处理前50个节点。覆盖按每章全部分段成功才计该章完成；空章、未读和未完成分别保留。逐章独立分析加层级归并不是带完整前文的连续阅读，不宣称角色知情地图或全书理解已完成。

每次发送、归并读取与迟到候选发布均复核冻结来源、授权和模型策略/注册表版本；研究计划、结果路径和结果指纹也受校验。暂停阻止后续节点，当前已发送请求完成后保存结果并落账；取消保留已发生费用，未知或已失败的付费请求不因重启、继续或重试而重放。恢复保存的记录与候选不等于重新发送模型请求。库与账本采用各自锁域，未形成跨存储原子事务。参考书全目录、原件、派生文本、定位、分析与批次/预算记录须完整备份；默认Git忽略，不能只备正文或丢弃journal。`tools/prepare_reference_books.py --import --backup`本轮生成的是私人语料及作品library绑定备份，不包含凭据或作品`.runtime`账本；若已有付费研究，要在停写状态另备实际计费作品的`project.json`、`.runtime/model-routing.json`和`.runtime/model-budget.json`，仅恢复私库ZIP不足以恢复跨存储预算。

a10当时交付四层资料设计的语料基础与候选研究流程，尚无人物知情/因果图、跨书比较、参考书语义/混合RAG、方法装配桥接或效果评阅；这些能力的当前合同分别见a11/a12补充，不把旧批次静默升级为连续精读。引用校验、分析覆盖与候选产出不代表文学结论正确、方法有效或作者批准；它们不写入`chapters/`、`memory/`或已批准规划，不替换固定样章，不训练模型。

## a12 连续研究、检索、整理与效果评测补充

本补充替代a10关于“尚无结构图、跨书比较和语义索引”的当前能力说明，旧记录仍是当时的阶段验收。原来的独立章段/四路归并批次继续可读，不被静默升级为连续阅读。

`library/studies/<study_id>/`保存不可变冻结计划、节点输入/精确请求、原始响应、成功结果、离线修复、图版本和CAS进度清单。连续结果绑定前检查点hash；只导出无缺口的成功前缀，未读/失败/未知单列。下一段仅收到最多6000字符carry笔记、最近30人物键/40事件键及20条旧证据；省略的历史明确计数，完整记录仍保留。补读标记回顾模式，不能回填初读。跨书比较限制每书24000/总48000字符，全部来源须有精确证据，跨书方法须至少两书；来源和图版本变化使旧方法与检索缓存失效。

### a12 规划现场选材与会话草案补充
