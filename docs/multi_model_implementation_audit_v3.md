# 多模型协作实施前审计与交付边界

日期：2026-10-19。依据作者对《多模型协作与路由设计草案》的“审计并实施”授权。本轮把注册表、角色绑定、候选工作流、调用预算和作者盲评落到现有 API-only 核心；不把软件升级视为任何作品章计划、改编或正式记忆的批准。

本轮使用本机临时作品和离线假服务验证，不自动拿真实作品做付费评测。设计中的模型能力排序、固定权重、自适应学习和多文件定稿不因本轮授权而被假定已经完成。

## 一、审计结论与修正

| 编号 | 原设计或基线的缺口 | 本轮处理与证据 |
| --- | --- | --- |
| R-A1 | 单一全局配置在执行时读取，无法保证排队节点仍发给预览时的模型 | 版本化本机注册表、作品角色策略和非凭据调用快照。配置版本变化使旧任务/后继失效；密钥只在后端解析，不进入任务或审稿。旧单配置须显式迁移，不静默覆盖。见 `studio/model_registry.py`、`studio/jobs.py`。 |
| R-A2 | 原 `context_sources` 仅 hash 加正式 revision，候选 A→B→A 不推进正式 revision | 任务额外绑定每份输入的历史版本 ID，候选发布及后继检查同时核对 hash/版本。已生成证据还保存 `target_version_id`；回退相同字节不使旧报告复活。见 `core/documents.py`、`core/model_artifacts.py`、`studio/workflows.py`。 |
| R-A3 | “独立审稿”原先仅为自然语言 Markdown，缺少程序核对原句与目标的契约 | 新增严格的证据审稿 JSON 和候选记忆 JSON。逐项原句必须等于指定 Unicode 半开区间；拒绝多余字段、伪造批准、无证据分数、错误身份和范围。引用存在仍不证明判断正确，界面始终显示候选性质。 |
| R-A4 | 把不同 profile ID 当作独立模型，可能同一接口/模型换别名即绕过 | 按规范化接口地址和实际模型 ID 核对主写/全部允许审稿目的地；归一 hostname 大小写、默认端口及尾斜杠。此项只是配置独立性，不宣称统计独立或不同训练来源。 |
| R-A5 | 单任务状态机没有后继关联、共享预算或提交中断对账 | 工作流每次只提交一个明确节点，GET/重启不会自动启动后继；工作流 ID 作为统一预算组。先持久 dispatch 意图，再提交关联任务；恢复只对账精确链接，缺失或重复链接进入不确定失败，不能被前节点成功覆盖后重放。 |
| R-A6 | 仅核对新候选，可能在原始来源或章计划已经失效后继续评审/抽取 | 每次后继检查所有既有节点的原任务快照、批准章计划、运行依赖和结果版本。读取工作流给出 `stale/drift` 说明，不启动模型。章计划变更仍须重新规划审批。 |
| R-A7 | 费用未知可能被当成零，失败/并行尝试各自认为预算充足 | 持久调用、Token 和美元预留由作品锁保护，所有节点及技术备用共用预算组。缺报价时费用保持未知；美元硬预算要求输入/输出价格。超时/迟到/无用量的调用保留不确定预留，不以“没有结果”推定没有费用。 |
| R-A8 | 修订多个分离问题时取最小至最大区间会把中间未选择正文也送去改写 | 只允许重叠或相邻证据合为一次选区；分离证据提示分别处理。每轮都须当前证据、精确候选和来源版本，最多两轮；区间外原文由后端保留。 |
| R-A9 | 没有可复核的作者文学偏好比较，模型标签可能影响判断 | NovelBench 锁定作者选择的两份候选、随机并固定 A/B 次序，默认隐藏来源路径/标签。投票后可显式查看来源；编辑、删除或已观察的回退使旧比较失效。投票不定稿、不训练路由、不生成排行榜。 |
| R-A10 | 通用任务重试生成新预算组，可能绕过已花费或不确定的流程额度 | 普通重试沿原预算组累计；工作流节点禁止通用任务页重试，须先核对流程与不确定计费。回归覆盖额度耗尽和工作流取消节点。 |
| R-A11 | dispatch核对后再次读取设置，竞争保存可能把后继发给新策略模型 | submit入队前核对流程冻结的策略/注册表身份，调用前再核对。回归注入dispatch到submit之间的两种配置变化和排队后的策略变化，均拒绝发送。 |
| R-A12 | 将请求model ID回填为response_model，误称服务端确认 | 请求和返回元数据分开；返回字段缺失、异常或含凭据时保持null，本机HTTP回归验证不虚构返回身份。 |
| R-A13 | 已释放的未发送记录不占调用次数，重复尝试可能写出超过自身读取上限的账本 | reserve额外限制每组32条历史尝试；第33次在写入前拒绝，原账本保持可读。 |
| R-A14 | 相同字节的新候选可能使界面旧审稿误显有效 | 审稿身份同时核对路径、hash和历史版本ID；候选变化立即禁用旧证据，纯函数与浏览器回归覆盖相同hash的新候选。 |
| R-A15 | 本地HTTP测试清空全部环境，Windows云端可能回落到系统代理，导致假服务连接失败 | 测试保留系统运行变量，仅隔离`VIBENOVEL_*`模型配置，并为本机地址显式设置`NO_PROXY`。新增不可用环境/系统代理回归，两个真实本机HTTP契约仍须成功，不跳过检查、不修改产品重试。 |

## 二、实际实施范围

### R1：显式角色与调用快照

同一作品的规划、正文、审稿、记忆抽取角色可各自绑定主模型及允许的备用；同一模型也可承担多个角色。每个生成节点由一个实际模型返回；后续局部修订仍按writer允许主备选择，可能与首节点不同，来源与尝试链保留。现有 OpenAI 兼容协议继续是适配边界，不因加入某厂商名字就宣称原生协议、结构化输出能力或文学能力已经全面验证。

多模型配置由专用设置接口保存到本机忽略文件；对外响应只有非凭据配置和 `has_api_key`。调用快照冻结地址、模型、容量、输出上限、报价、角色策略版本；模型不能根据待写正文改变这些字段。

### 受控候选工作流

后端工作流API支持“已应用章计划→候选起草”或“已有文稿→候选修订”，再由作者明确推进到证据审稿和候选记忆抽取。当前多模型页面从已有文稿修订开始；新章起草仍从原已批准章计划入口发起。启动第一节点和每次后继推进都是有界 API 任务；关闭网页后任务与流程记录保留。作者可暂停、取消，运行中断后需核对记录，不能自动重新发送可能计费的请求。

`ready` 表示所选候选节点就绪，不表示正式章节或记忆已提交。证据审稿引用同一冻结候选；候选记忆只记录带原句出处的建议，写在 `reviews/`，不读取或改写正式 `memory/`、`chapters/`。规划、传言、回顾和推断不能仅凭一条引用升级为已发生事实或人物知情。

局部修订由作者选取已定位证据发起，并绑定当前候选版本。修订不自动更改章计划、事实权限或正式正文；改变计划的建议仍应回到已有审批流程。最多两轮是上界，不是每章固定消费。

### 有限技术备用与预算

只允许事先列入对应角色的备用目的地，有限处理明确可重试的暂时 HTTP 故障。认证错误、无效请求、来源失效、预算不足或不确定超时不能借切换服务商绕过。应用层不承诺外部请求 exactly-once，也不能仅凭本地预算保证厂商实际账单的硬上限。

Token 采用显示的保守估算和厂商返回用量；估算不是厂商 tokenizer 的精确计数。报价由作者登记，不能当作已经核实的厂商官方价格。没有报价或完整用量时，不虚构“实际美元费用为零”。

### NovelBench 的本轮含义

本轮交付双候选作者盲评及版本锁定，支持记录偏好、平局、备注和独立导出比较。它用于积累可回看的作者决定，没有自动文学分数、跨模型胜率榜、学习式路由或额外付费评委调用。正文自身可能包含来源提示，隐藏配置标签不能保证彻底盲化。

## 三、存储与权限

| 记录 | 位置与性质 |
| --- | --- |
| 本机多模型配置 | `config/models.local.json`，包含本机凭据，排除 Git；只由专用接口脱敏读写 |
| 作品角色与预算策略 | `.runtime/model-routing.json`，版本化软件策略，不是小说事实 |
| 持久预算 | `.runtime/model-budget.json`，保留已知、未知和未发送费用状态，不随失败自动清空 |
| 候选工作流 | `.runtime/workflows/<id>.json`，持久步骤、来源、关联任务和提交意图，不是正式小说批准 |
| 原子任务 | `.runtime/jobs/<id>.json`，沿用任务生命周期和候选发布恢复记录 |
| 模型证据与记忆建议 | `reviews/` 的独立 JSON，严格候选身份；本文不以它们代替正式记忆 |
| 作者双候选盲评 | `reviews/bench-<id>.json`，DocumentStore 历史和单文件 journal；锁定两份正文和 A/B 次序 |

正式章节与多份记忆共同审批、事务应用及失败恢复仍属于 M2。当前 `ApprovalStore.apply` 和 DocumentStore journal 是单目标协议；不能将多个单文件批准串行调用描述成一次原子定稿。盲评票、流程完成、审稿建议和记忆候选均不具备正式写入权限。
