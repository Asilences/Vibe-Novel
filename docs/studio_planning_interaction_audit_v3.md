# 大纲到规划包的交互审计与验收

日期：2026-10-20。任务为软件维护，不授权真实作品的规划批准、正文定稿或额外付费请求。

## 问题与修复

| 可复现问题 | 对作者的影响 | 本轮修复 |
| --- | --- | --- |
| “规划包”选择框与“导入大纲与生成规划／预览创作规划”使用不同名称 | 已生成大纲的作者不知道在哪创建规划包 | 创建区、预览、确认和下一步统一使用“规划包” |
| 从人物、时间线或文风页进入时，生成区默认折叠；无包空态没有操作 | 作者只看到“尚无规划包”，容易认为没有创建能力 | 无包自动展开生成区，显示紧凑步骤说明；只保留表单“预览规划包”主动作，无来源时可从零构思 |
| 创意页的选用和后续规划入口位于长表单底部 | 已完成总纲后仍需反复翻找下一步 | 页首按已有候选／已选用／来源变化显示下一步；移除底部重复创建按钮 |
| 已选用的总纲被编辑或删除后，当前页局部状态未必立即变化 | 仍可能看到旧版继续规划入口，直到后端拒绝 | 对当前文档列表中的路径和内容指纹实时核对，失效快捷入口；后端完整版本门禁仍保留 |
| 再次生成规划包时，包选择框会保留原来选择 | 生成完成但作者仍看到旧包 | 新增“查看最近生成的规划包”，直接选择本次结果并定位展示区域 |
| 预览按钮禁用但来源条件缺少就地说明 | 不知道需要先选用总纲、配置模型还是导入材料 | 在表单旁按当前来源和模型状态解释阻塞原因，明确预览零模型调用 |

普通导入或手写大纲可以直接在“大纲与卷章”选择来源。由从零构思生成的 `story-outline-*` 候选须先在“创意与定位”明确选用。两者不可混为一个额外审批要求。

按作者对冗余入口的反馈，无包状态不再同时提供顶部创建、工具栏新建和空态创建三个按钮。创建表单保持展开，唯一主动作是“预览规划包”；工具栏“新建规划包”仅在已经存在规划包时显示，用于展开创建表单。空态只说明结果将显示于此。创意页的顶部按钮承担跨页面的下一步导航，底部仅显示选用状态。

## 实际操作链路

创意与定位 → 保存构思 → 预览并生成初版总纲 → 审阅并选用 → 创建规划包 → 选来源及本批1–10章 → 预览规划包 → 确认并生成规划包（付费） → 查看候选 → 提交整包审批 → 批准并应用 → 提取章计划 → 单独批准并应用 → 按批准章计划起草 → 审稿 → 作者确认正文提案 → 批准并应用 → 导出正式章节。

人物、世界、伏笔、时间线与写作风格页是同一个规划包的不同视图。规划包及章计划都描述未来策划，不会因为批准规划而成为已发生事件。保存、选用、批准、应用和模型生成是不同操作。

## 本轮离线验证

- 新增 `tests/test_author_journey.py`，通过真实 HTTP 接口串联独立合成足球经营故事：构思、总纲、选用、规划包、整包审批、章计划审批、草稿、审稿、正文审批及正式导出。
- 整条链路仅使用本地假模型，恰好4次调用：总纲、规划包、草稿、审稿各一次；保存、预览、选用、审批和导出不增加调用。
- 未选用总纲时规划预览拒绝；未批准提案不能应用；整包应用后、章计划未应用前仍不能起草。正文提案批准后、应用前正式文件仍不存在。
- 草稿和审稿不会写入正式章节；完整链路不将模型规划或提案写入正式人物设定及记忆。正式导出只含已应用正文，不混入规划包或审稿候选。
- 新增前端来源变化回归，覆盖已选用总纲编辑、删除与正常内容匹配；TypeScript检查通过。它不是完整来源历史检查，完整依赖版本仍由服务端核验。

浏览器截图、生产构建及其他模块的全功能验收以本轮总审计记录为准。本测试不评价真实模型的文学效果，不调用真实付费 API，也不表示已经实现多文件事务定稿。
