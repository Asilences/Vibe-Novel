# VibeNovel Studio：审计与实现设计

日期：2026-10-18。依据作者本轮“审计、设计并实施”要求，将本地 Web Studio 列为 v3 必做项。本文是软件设计；不批准任何小说情节、章节或设定。

## 审计结论

采用独立 React + TypeScript 前端、FastAPI 应用层、共用 NovelCore。界面按作品导航、文稿工作区、Agent 面板组织；中间编辑区优先，可收起两侧。拒绝让浏览器承担唯一的任务生命周期，或让模型获得正式作品写入工具。

| 原建议 | 审计与决定 |
| --- | --- |
| 直接复用 Harness | 仅借鉴任务与审批交互，不引入其插件执行系统或复制代码。官方仓库确有 Web、桌面开发入口、MIT 许可和开发预览提示；升级兼容性不能当作稳定契约。 |
| 首版六个页面 | 全部提供入口，先完成真实作品/文稿/审批/任务闭环。世界观页展示作品实际资料，未录入时显示空状态；不编造人物图和时间线。 |
| Tiptap 富文本 | 首版提供无损 Markdown 源码编辑与清洗后的阅读视图；暂不引入富文本回转。Tiptap、行内批注在后续增加，必须先验证不会改变未编辑的源文。 |
| SQLite + Markdown 双存储 | Markdown/JSON 仍为权威源。本期没有需要 SQLite 的跨文件查询规模，不增加不可恢复的第二份权威。后续 SQLite 只做可重建索引。 |
| 高自主写作与审批按钮 | 作者控制不等于同权限进程隔离。按钮调用核心的基线、哈希和状态检查；本地单用户服务不宣称识别真正的人类点击。 |
| 生成、暂停、重试、恢复 | JSON 任务持久化，浏览器关闭不影响后端任务。后端重启将运行中的请求标记中断，需要明确重试；已返回的候选可恢复发布，排队、暂停和 Codex 等待回填状态保留。暂停排队任务可恢复，运行请求中断后不承诺从模型 token 断点续跑。 |
| Codex/API 自由切换 | 首版 API 使用 OpenAI 兼容 Chat Completions；Codex 为可导出上下文、回填候选的交互接力。自动 App Server 会话、流式审批为下一阶段，界面不冒充连接成功。 |
| 一键定稿并更新所有记忆 | 本期支持每个目标文件的提案、审批与可恢复应用。章节与多份记忆的原子批量定稿仍需要 M2 多文件 journal 验收，不能用多个 replace 假装事务。 |

核验的官方资料：[DeepSeek Harness README](https://github.com/deepseek-ai/deepseek-harness)、[许可](https://github.com/deepseek-ai/deepseek-harness/blob/master/LICENSE)、[安全说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/SAFETY.md)、[Codex SDK](https://developers.openai.com/codex/sdk/)、[App Server](https://developers.openai.com/codex/app-server/)。SDK 是服务端集成路径；App Server 提供持续会话、事件和执行审批。执行审批不代替小说改编的业务批准。

## 首版产品范围

1. 作品控制台：创建、切换四类作品，显示真实文稿、来源、审批与任务数量。
2. 大纲工作台：MD/TXT 原字节导入、来源标识与章节标题导航；作者编辑候选大纲、版本历史、扩写任务、提交批准大纲提案。
3. 正文编辑器：作者创建/编辑草稿、显式保存、冲突提示、版本恢复、局部改写候选及独立审稿；正式正文只读，修改走提案。
4. 审批中心：目标、理由、影响、完整前后差异、基线、批准/驳回/应用；拒绝、过期或被篡改提案不能应用。
5. 故事资料：按人物/设定、事件、状态、伏笔、摘要浏览真实文件；录入也走提案。自动人物关系抽取、语义检索、题材专用赛程等留后续。
6. 任务监控：能力与配置状态、任务持久化、取消/暂停/恢复/重试、接力提示词及结果、实际 usage；无报价时成本显示未知。

## 数据与审批

保留 M0 的 `project.json` schema_version=1，不把模型配置或 UI 偏好塞入此严格配置。版本/审批状态保存在作品的版本化 JSON 中，锁与运行任务位于 `.runtime/`。可编辑路径限于草稿、来源大纲、候选大纲和审稿。原件保持不可修改。

写入带 `expected_hash`：null 仅用于新建；旧内容不匹配返回 409。恢复旧版产生新版本。正式文件由提案携带 before/after、目标作品、内容哈希、正式基线指纹和单调 revision；批准与应用分别执行。通过核心观察到的修改会推进 revision，防止 API 内的 A→B→A 复用批准。未被观察的外部 A→B→A 无法仅靠磁盘最终内容检测；不宣称具有操作系统完整审计能力。

模型只接收选定来源、已批准计划和可用的作品证据；资料中的命令视为数据。生成结果只落候选/审稿路径，发布前再次检查输入及正式基线。草稿任务必须绑定仍有效的已应用章计划。未检索完整历史时须在审稿中注明范围。

## 本地服务与边界

默认仅监听 `127.0.0.1`，前端构建产物与 API 同源。拒绝陌生 Host、跨站 Origin/Fetch 请求，所有变更请求要求本次服务随机令牌；不开放任意本机路径、Shell、环境变量读取或密钥写入 API。限制请求/文稿体积，路径校验复用 NovelCore 并阻断链接与 junction。令牌用于浏览器请求隔离，不是多用户身份系统。

网页上传原件受 15 MiB JSON 请求上限限制，默认最多 10 MiB 原件；大于网页上限且在 CLI 配置范围内的原件可通过 CLI 导入。编辑文稿上限 2 MiB，导入预览 16 MiB；大量源材料应分卷/分章。单个作品历史 JSON 暂限 64 MiB，后续拆分不可变对象存储，不宣称当前已适合无限版本长篇。

API key 只从启动后端的环境读取；不会发往浏览器或任务记录。仅作者启动的任务调用已配置的模型，不在启动时测试付费生成。错误记录不保留上游原始响应中的凭据。

## 验收约束

用临时作品验证创建→导入→候选大纲→提案批准应用→章计划→生成接力→草稿→审稿→章节提案→正式导出，另测跨作品、路径越界、旧写入、旧批准、外部漂移、崩溃恢复、关闭前端及重启后端。前端必须完成 TypeScript 构建及实际浏览器交互；不把页面截图当作后端验收。API 真正服务商调用仅在有相应配置且作者主动运行任务时发生。
