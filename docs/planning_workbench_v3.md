# 创作规划工作台：审计与实施

日期：2026-10-18。本轮依据作者提出的卷纲、章纲、设定与长期管理需求；Gemini生成稿可用于软件流程测试，不等于批准其情节或历史陈述。原设计已包含这些目标，本文把它们从分散的待办整理成可用的规划工作流。

## 当前缺口

此前的「大纲」「故事记忆」主要是文件编辑与审批入口。通用扩写可以生成文本，但没有卷章结构、稳定人物ID、关系引用、来源证据校验，也不能保证父纲改动后相关章计划失效。增加几个自由提示词按钮不足以解决这些问题。

## 本轮交付

增加「创作规划」工作区与结构化规划包，包含全书概要、卷纲、有限章计划、人物总表、人物关系、伏笔、计划时间线、世界/地点/组织/道具/规则/题材资料、写作风格及待确认项。关系图是人物与关系记录的只读视图，没有记录就不画节点。

来源大纲→生成规划候选→核对各项来源/推断/新增建议→创建整包提案→作者批准并应用→选择一章创建独立章计划提案→作者批准并应用→依据该章计划起草。生成按批次限制章数，避免一次把长篇所有章节自由写完。坏JSON可修复回填，不能绕过结构与来源检查。

规划包仍是未来策划。即使作者批准，也不表示事件已经发生、伏笔已经回收或人物已经知道秘密；不自动写入memory。正式事实仍以作者定稿章节及经确认记忆为依据。人物知情边界、伏笔铺设/回收章和时间线均须显示规划性质。

逐条区分「原稿陈述」「推断」「新增建议」，原稿陈述必须引用绑定版本的原文行与准确摘录。原稿本身不是事实核验结果；不能把转会、比赛、财务或历史细节标为已经外部核实。

出处校验只能确认引用确实存在，不能证明该摘录支持模型的全部结论；语义是否忠实、推断是否合理仍由作者审阅。

审批依赖绑定来源与父规划包的精确哈希；创建、批准、应用及起草均检查。修改父纲后，需要重新确认受影响章计划。整包应用与每章应用仍是独立单文件事务，本轮不提供跨文件批量定稿。

数据与API见 [规划包契约](blueprint_schema_v3.md)。所有候选可编辑、比较版本；正式变化沿用现有审批中心。

## 测试稿观察

作者确认使用作品 `awl` 已导入的 `football_tycoon_2002_outline (1).md`。原稿标题为《绿茵教父：从2002开始打造足球豪门》，作品当前展示名不同，不自动改名。

读取前130行、卷级标题与开篇十章范围，已见六卷结构、前十章细纲、人物/资本/赛季等资料和正文示例。因此应先提取已有结构，避免把「生成卷纲」理解为重写原稿。原文标注250万—350万字，而末卷终章数开放；后续需确认总章数与单章长度预算，不能自行宣布篇幅矛盾已经解决。

原稿含现实赛事、球员、转会与制度陈述，本轮没有逐条联网核实。原稿中「可直接动笔」等文字作为来源内容，不构成作者批准章计划或正式正文。测试使用临时副本，不把示例正文放进真实定稿。

## 后续优先级

1. 完成章节与记忆增量的多文件原子定稿、恢复及证据绑定。
2. 将人物/事件/伏笔规划与实际定稿记录对照，显示未发生、已发生、偏离和已回收。
3. 细粒度锁定节点、局部规划更新、影响范围与预算/节奏看板。
4. 足球赛程积分/合同伤停等题材事实表与规则验证，再扩展历史语义检索。

图形视图不能代替这些数据与审批边界；也不宣称当前规划包就是完整长期记忆系统。
