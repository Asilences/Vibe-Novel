# VibeNovel Studio：书籍方法提炼与使用设计

日期：2026-10-19。状态：**a9已实现L2-A分析/提炼与L2-B采用/装配；L2-C评阅/对照试用待做**。作者在选型设计后明确“开始实施”。本轮按原生API方案实现所选机制，没有安装宿主技能或复制上游代码；实际交付与设计差异见第10节，数据合同以 `storage_contract_v3.md` 为准。

本文是 `knowledge_library_design_v3.md` 9.5–9.6的具体吸收方案。面向作者的名称为**提炼创作方法**，资源归入已有设计的“方法与模板”；不增加独立的顶层拆书平台。这里的Skill是可复用的声明式任务方法，由NovelCore装配给API模型使用。

## 1. 选型决定

| 项目 | 本次确定吸收 | 在Studio中的结果 | 集成方式与阶段 |
| --- | --- | --- | --- |
| book-to-skill | 分离分析与生成、阅读地图、小入口与按需详解、已有分析续用、增补资料的差异预览 | 分析报告→方法候选；按任务加载必要方法和出处，不每次发送整本书 | **首批采用其组织机制**；由现有API体系实现，不直接引入其CLI、宿主目录及依赖安装链 |
| Cangjie | 方法卡、来源/可执行性/任务价值分别检查、普通参考与证据不足项分流、边界反例、代表任务验证 | 有出处、输入输出与使用边界的候选卡；作者修改/采用；独立试用记录 | **首批采用其方法设计机制**；映射统一资料实体，不建立`.cangjie`第二套权威、不引入其Agent宿主及自动进化链 |

| Docling / MarkItDown | 尚不决定代码依赖 | 与L3/M4共用解析器候选评估 | 待中文来源定位、格式覆盖、Python版本与依赖成本验证后选择；不能替代方法提炼 |

首批采用的是已明确选择的机制，**不是宣称上游已经集成、安装或通过小说效果验收**。不以高星自动决定运行依赖，不照搬五Agent并行、自动全网采集、模型自评质量分或技能自动更新。

## 2. 作者页面与操作

入口一：**资料中心 → 来源详情 → 提炼创作方法**。入口二：专题详情选择其中的明确来源版本，再进入同一流程。参考小说优先显示“分析创作技法”，职业手册/写作教程显示“提炼方法”；普通考据可只整理事实笔记和术语，不强行拆成技能。

```text
选择来源与阅读范围 → 选择用途 → 模型/输入/预算预览 → 分析报告
                                                      ↓ 作者选择继续
用于本书任务 ← 作者修改并采用 ← 方法候选与出处核对 ← 提炼方法
                    ↓ 可选
          同一测试输入：不使用方法 / 使用方法
```

沿用资料中心列表与详情布局，不占正文编辑器的固定第三栏。设置/缺密钥处理后能回到原步骤，未保存的用途、范围和作者修改受离开页面保护。

| 界面 | 作者看到与可操作的内容 |
| --- | --- |
| 提炼设置 | 来源版本、目的（规划/审稿/表达修订/职业方法）、选择章节/片段、已存在分析、缺失资料；可只做分析 |
| 调用预览 | 明确的计费作品、模型/服务商、实际发送区间、外发政策、预计调用及输出上限、共享剩余预算；价格缺失时不虚构金额 |
| 分析报告 | 章节地图、结构观察、实际阅读覆盖、未读/失败部分、可提炼方法、普通参考、证据不足项；查看原文或补材料后继续 |
| 方法与模板 | 候选/已采用/归档筛选；按目标和适用场景查找，打开方法卡查看步骤与依据；作者可逐项修改或保留分析而不发布方法 |
| 方法详情 | 使用/不使用条件、输入、步骤/分支、预期输出、边界反例、原文依据与解释、原书案例与合成练习、评阅与试用记录、使用影响 |
| 更新与试用 | 新旧方法差异、受影响引用；同一输入的两份输出和费用，作者标记有用/无明显改善/变差/待判断并附理由 |

无作品时可以浏览、整理个人库。**首期API提炼/试用必须显式选择一个真实作品作为任务与预算归属**，在预览中显示；结果先归该书私有方法区，作者可另行收藏到个人库。选择计费作品不自动读取它的正文、人物或设定；只发送本次明确资料与任务输入。不创建隐藏小说、静默借用当前书或拿另一作品预算。无作品的个人库付费任务需未来独立的工作区路由/账本/恢复合同，首批不做。

首批建议试点四种任务：场景节拍与变化、人物动机与知情边界、悬念/伏笔的规划与审查、保留事实的表达审校。它们是产品支持的用途，不是已经从任何书中抽取、验证或预置上线的技能；伏笔方法的使用也不证明某条伏笔已经回收。

## 3. 分阶段提炼流程

1. **本地预处理**：核验来源版本/格式，生成可提供的目录、段落与位置，记录解析遗漏。无需模型就能完成的校验、计数和定位在本地进行；不凭书名或模型记忆补写书中方法。
2. **分析资料**：只读取预览列出的章节/片段，产生阅读地图与候选方向。小范围分析不标成整本书已读；覆盖按解析、发给模型、模型产出可定位依据分别记录，不能将“发出全文”称为“模型完全理解”。
3. **提炼候选**：作者选择已有分析和用途后启动；同版本有效分析可复用，不重复付费重读。方法、普通参考、待核实内容和不采用理由分开保存；不强制每章产出一个技能或达到最低数量。
4. **核对与可选评阅**：服务端核验ID、版本、区间、原句及依赖是否存在；这只证明引用对应，语义支持程度仍是评阅结论。模型评阅可选，另列调用与预算；同模型再次回答不称为独立证据或独立验收。
5. **作者采用**：作者查看并修改候选，显式采用某版本为方法资源；采用只允许后续按政策用于任务。未经试用也可明确标“已采用、未试用”，不把未运行评测标成通过。
6. **任务使用与更新**：按已保存的书级策略自动选取，或作者手选覆盖；新增资料和作者修改均产生新候选/版本，展示差异，不覆盖手改内容。本书可继续固定旧版；只有明确改选、撤回、损坏等按资料中心合同使依赖失效。

默认单份资料、小范围、分阶段运行。大书的分章调用、查询改写、复核和试用全部计入同一流程预算；开始前列出调用计划与最大次数，未发出的后续阶段不能在页面打开或保存时自行执行。补读超出原范围/预算时先更新预览；暂停、取消和服务重启均不重放状态未知的付费请求。

未来增补多份来源时保留各自ID和证据，支持相反说明，不把合并后的文本当成一本无冲突的新书。首期专题入口只在范围/调用上限内选取明确来源；需要多源综合和跨章节全量抽取的复杂任务留到L3评估。

## 4. 方法卡与分析的拟议数据合同

下列是现有资料中心实体的专门类型，不创建另一套正文、人物、风格或记忆权威。具体schema、大小上限、路径白名单及API字段在实施时进入独立library合同并验收；本轮不提前修改 `storage_contract_v3.md`。

| 类型/字段组 | 拟议内容与约束 |
| --- | --- |
| ReferenceAnalysis | 来源/抽取版本、用途与任务ID、目录地图、解析与实际输入覆盖、观察/候选方向、遗漏、精确证据引用、revision/hash |
| MethodCard身份 | 复用Entry的stable ID、类型method、标题、作用域、revision/hash、作者/模型归属；关联分析的精确版本 |
| 任务契约 | 任务目标、可用任务种类、适用/不适用条件、必需输入、步骤及分支、预期输出、停止条件/局限，不含工具执行权限 |
| 依据与解释 | Source/Excerpt精确引用；原文陈述、模型解释、作者改写分开；原书实例与合成练习分别标识 |
| 路由与关联 | 用途/关键词、依赖或相邻方法ID和固定版本、简短入口、必要详解/参考；依赖须有界、去重，拒绝循环和跨范围加载 |
| 评阅记录 | 各项检查的执行者/模型、输入版本、结果/缺口及证据；确定性引用校验与语义判断分开，不用一个verified布尔值代表全部正确 |
| 作者选择 | 采用/取消/归档的显式决定和方法版本，复用BookBinding及书级政策；不借用正文Approval或创作总纲选用记录 |
| MethodTrialRecord | 测试输入与条件、无/有方法的输出版本、各自模型/调用参数/尝试与费用、作者判断、遗漏；全部为候选测试资料 |
| MethodRun | 复用流程身份与共享预算的关联、阶段及输入/输出清单、发布/恢复意图、故障和未知请求记录；是持久状态，不是可清空缓存 |

整理状态、来源核对状态、作者采用状态、任务外发政策、试用完成情况分别保存。“通过结构校验”“作者采用”“已完成一次试用”均不意味着文学质量合格或可改写正式内容。

同一份方法卡是内容权威；小入口、索引、任务提示片段和将来的受限SKILL.md导出均由其版本派生。作者修改卡片后旧评阅/试用保留历史并显示所测版本，不能继续冒充新版已通过。导入SKILL.md只能先成为候选文本；脚本、命令、外部链接、工具权限及自动安装配置不执行、不继承。

## 5. Studio如何自动使用方法

复用资料中心的手动/自动推荐/有界自动模式。作者在书级选用并启用方法用途后，常规任务不要求逐条重复批准；未采用、撤回、依赖损坏、超范围或未允许外发的方法不能自动入模。

装配顺序为有效作者要求与必需故事上下文→明确必选方法→预算内的自动补充方法与证据。方法是本次任务的辅助要求，与已批准计划、角色知情边界冲突时显示冲突并请作者调整；不得靠换方法修改原计划或把职业教材变成故事事实。

初期以任务类型、作者目标、标签/关键词与章计划本地匹配短入口，默认最多推荐3个补充方法，再按预算加载其必要步骤、边界和来源片段。有效作者要求不靠相似度召回；必选内容超限时要求调整，不静默省略。关联卡/详解也占同一上限与上下文预算，不因方法间引用而无限递归。

预览和实际输入记录方法ID/版本、选择政策版本、选择/省略原因、实际加载内容及来源区间；发送前、排队执行、结果发布、恢复均重验。固定旧版仍有效时保持可用；本书明确改选后的A→B→A不复活旧任务。已完成任务留历史快照，旧结果不得伪装为当前有效候选。

Book2Skill负责整理方法，RAG负责补取依据。首批不要求模型自行运行搜索工具；先由后端在允许范围检索、装配，再调用API。如后期加入模型逐轮检索，另定义允许工具、调用上限与账本，不让导入的技能文本赋予系统工具权限。

本节是未来改造位置，**不代表这些接口已经存在**。本轮只读核查了相关枚举与边界。

| --- | --- |

| jobs当前pending result主要是单文本/单路径；库分析可能产生多卡 | 暂存候选包、校验全包、最后原子发布manifest；失败不暴露半套可用卡。恢复重验来源/选择/政策，不重发模型请求；不宣称因此实现M2正式多文件定稿 |
| `core/briefs.py` 输入manifest；现有规划/修订任务另有装配路径 | 增加统一方法/资料选择层并显式接入各任务；不因扩展写前包就声称总纲、规划、已有稿审校已自动接通 |

分析地图、方法卡、试用输出属于LibraryStore管理的派生/候选对象；正式`chapters/`、`memory/`、批准章计划和既有审批记录不接受这些任务直接写入。作品级方法任务与个人库收藏分两步发布，不暗示已有跨库事务。

## 7. 试用与验收

方法有效性先用可分发的人工测试材料、离线provider验数据与交互；真实书籍及付费模型试点留给后续明确选定的材料与预算。本轮未运行以下尚未实现功能。

1. **出处与覆盖**：只有书名或缺页时不声称拆书完成；中文、CRLF、emoji、重复原句仍定位到精确版本和区间，清洗不覆盖原件；引用存在与语义是否支持分别记录。
2. **内容与状态分离**：事实笔记、技法观察、可执行方法、待核实项可并存；作者采用不自动填成已评测，不使案例剧情成为本书事实。
3. **输入、费用与恢复**：预览/实发一致，按需加载可查；分章/复核/试用共同受调用与预算上限约束；双击不重复提交，取消/重启/未知请求不自动重放，候选包发布中断不出现半套可用资源。
4. **权限与作用域**：无作品时不会默借预算；计费作品不扩大阅读范围；未采用/未允许外发的方法不入模，资料内指令与导入脚本不执行，不扫描其他小说，不写正式正文和记忆。
5. **版本与更新**：发布新版不使固定旧版自动失效；明确改选/撤回后阻止排队、迟到结果、人工恢复绕过；A→B→A、方法手改、循环依赖及重新提炼分别测试，保留历史依据。
6. **真实任务而非触发测试**：冻结同一测试输入、模型及生成参数，分别查看有/无方法的实际输出和成本；检查任务完成、遗漏、越界与作者判断。模型输出可能有随机性，单次改善不代表稳定增益；方法触发/格式合格、模型自评均不替代实际任务结果。

试用限规划、审稿、表达候选，不自动推进章计划批准/定稿。需要改良方法时另起版本，作者保留对候选及测试结论的判断。

| L2-A 分析与提炼 | 设置/分析报告/阅读地图、可复用分析、API候选方法与来源校验 | 明确范围、两阶段预算、无正式写入；选型与设计已确定，功能待实施 |
| L2-B 采用与使用 | 作者编辑/采用、方法路由、RAG证据与任务manifest、版本/恢复门禁 | 写前规划、证据审稿和已有稿修订分路径验收；常规自动选材沿书级策略；待实施 |
