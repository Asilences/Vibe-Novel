# a11 参考书研究到创作方法的桥接

日期：2026-10-20。作者要求继续实施，承接a10参考书架与章段研究。目标是让有证据的研究方法能进入已有的个人资料库、作者采用、本书固定选用和任务取材流程。本轮没有把研究候选自动批准为方法、小说事实、正式计划或文风样章。

## 使用流程

1. 在参考书架打开成功研究节点的完整结果，或最终归并。没有方法时显示空状态；存在方法时，作者选择1–6项并预览。
2. 服务器重新读取成功节点、所有前置结果及原文范围，返回待保存的步骤、局限、证据和预览hash。客户端只提交索引，不提交方法正文或来源对象。
3. 显式保存为个人方法候选。默认local/inbox/unverified/AI_SUGGESTED、未采用；保存与预览均不调用模型。
4. 进入个人方法卡，回查固定书籍版本原句，编辑适用情境、输入输出、步骤、限制和作者摘要；明确采用当前方法版本。编辑清除旧采用记录，来源保持只读。
5. 选择作品、用途，点击用于本书固定个人卡版本。任务按原有手动/推荐/有界自动策略取材，预览记录实际发送文本与外部依赖；选入本书本身不发送模型。

UI中的成功节点和最终归并均提供入口。未知保存结果保留同一幂等键，不靠重新选项发出另一份保存；409冲突保留作者选择，重新预览后才能发布。导航及关闭保留现有未保存保护。个人卡与本书绑定显示只读研究出处，并可按固定edition回查精确区间。

## 来源与存储

新增`core/reference_methods.py`只读构建及验证研究来源，`LibraryStore`提供preview_reference_methods和publish_reference_methods。`reference_jobs.py`与桥接共用冻结计划校验投影，避免两处规则漂移。

方法卡保留独立`research_origin`：书籍ID/书名、解析版本、批次及节点、结果hash、计划hash、授权epoch、方法索引、精确方法证据，以及完整有序原文/结果依赖的count/hash摘要。批次指针保有完整范围，验证时重新读取整条依赖链；不能只核当前节点而放过前置原件或归并候选。结果路径严格由本书/edition/batch/node推导，不接受客户端任意路径。

origin最多32KiB；普通任务新增研究依赖总共最多256KiB，超限拒绝并要求缩小范围，不截断。不会将整本原文和上千依赖数组复制到每张卡、绑定和普通任务。a9的来源10MiB、记录16MiB、清单8MiB、版本数量与写作资料字符预算均不扩大。

库发布使用原有单库不可变对象、清单和journal，创建entry和bundle在同一清单revision可见。来源在预览、发布前、journal恢复、编辑、采用、固定选用、任务装配及快照再验时检查。不同库/预算账本仍不是共同原子事务，不保证同权限外部写入的分布式隔离。

同一幂等键/同一预览返回原bundle的创建版本，不覆盖作者后来编辑的卡；异内容拒绝。客户端不能在普通新卡注入研究origin；编辑旧卡即使省略该字段，服务器也会保留旧来源，不允许改类型洗掉依赖。书籍授权撤回再恢复不能复活旧候选。来源失效后仅允许作者保留全部内容和来源、收紧外发、归档或撤回，清除采用；不能借终止操作更换内容、放宽权限或恢复使用。

## 入模与证据边界

普通任务新增`typed_deps.kind=reference_research`，封存origin，发送与发布沿用库快照校验。研究原句留在来源核对区，不伪造a9普通source_refs或source_fragments；实际没有发送的研究引文不能声称模型已读。当前卡片摘要/方法文本按作者外发政策进入任务，来源依赖继续有效；原书信息不能因此成为本书人物知识或历史事实。

失效的自动可选研究方法/绑定会记录遗漏并跳过；手动选定或自动必选失效则明确拒绝。所有原a9采用和政策检查继续生效。旧分析/提炼接口只接受精确source_ranges；generic publish_method_bundle亦拒绝含研究依赖的再次提炼快照，防后续错误接入导致来源丢失。若要补读，仍从新的原文范围建立研究。

## HTTP与运行

新增本地同源/CSRF保护的接口：

```text
POST /api/reference-books/{book}/batches/{batch}/nodes/{node}/methods/preview
  {method_indices: [0, ...]}
POST /api/reference-books/{book}/batches/{batch}/nodes/{node}/methods
  {method_indices, expected_preview, idempotency_key}
```

只发布到个人库，不允许客户端指定任意scope、作品、方法正文、模型或文件路径。缺失、过期、超界及失败节点均拒绝；没有真实API调用，也不占新的模型预算。模型研究本身仍需a10明确范围及预算启动。
