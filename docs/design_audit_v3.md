# VibeNovel v3 设计审计

日期：2026-10-18。范围：原始设计 §0–13、当前项目全部文件清单与三个 Python 工具。原设计归档为 `docs/VibeNovel_v3_original.md`；本报告是工程修订意见，不是小说设定审批。

## 结论

产品方向可执行，但设计不能直接作为完整实现契约。先补权威源、版本、恢复和输入边界，再实现运行基础。审计起点的 v2 只有 Markdown 模板和三个标准库脚本，没有可安装包、工作流引擎或测试；当时文件夹不是 Git 仓库，小说定位未填写。本次为软件维护，不选择或虚构题材。

## 审批安全的实际边界

原设计 §1 已正确承认同一操作系统写权限无法通过提示词强隔离。本地 CLI 的确认输入或 `--author` 字段只属于协作流程，不能叫作“认证人类”。真正隔离需要独立批准通道、进程权限或受保护仓库；原目录在审计起点没有 Git，不能假设受保护分支已经存在。后续创建 Git 也不意味着已经设置远端分支保护。
