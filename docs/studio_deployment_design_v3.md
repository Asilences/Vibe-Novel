# Studio 常驻运行与远程访问设计

日期：2026-10-21。状态：**设计与只读环境核对，尚未部署服务器**。本方案解决长期使用时入口稳定、服务常驻及跨设备访问的问题；不迁移私人书库、小说、模型密钥或费用账本，不修改现有服务的网络边界。

## 1. 使用入口

| 场景 | 建议入口 | 后端位置与约束 |
| --- | --- | --- |
| 日常在本机写作 | `http://127.0.0.1:8000/` | 固定本机8000端口，使用真实工作区；书签保持不变 |
| 隔离验收 | `http://127.0.0.1:47328/` | 本轮临时隔离工作区和独立共享测试账本；不改成日常入口 |
| 使用远程服务器，先供本人访问 | `http://127.0.0.1:18000/` | 本机SSH隧道转发到服务器`127.0.0.1:8000`；与本机8000并存 |
| 未来固定域名 | 待作者指定实际域名 | 先完成远程身份认证、会话与跨站保护、TLS和访问边界设计，再配置DNS/HTTPS |

固定端口、进程常驻、固定域名是三个独立问题。当前源码启动默认就是8000，稳定入口不需要先购置域名。测试服务使用临时端口是为了避免对真实小说或运行中的日常任务产生影响。

日常服务启动时显式绑定工作区与前端目录；端口被占用时先确认占用者和所用工作区，不自动切到另一个随机端口，也不直接结束未知进程。前端静态文件由同一个后端提供，日常使用不依赖Vite开发服务。

## 2. 本轮服务器只读核对

服务器通过已有SSH配置，以BatchMode和严格主机密钥检查连接成功。实际地址、端口及账户只保留于被Git忽略的私人工作记录；公共文档统一使用`USER`、`HOST`、`PORT`占位，不填写虚构域名。

| 核对项 | 只读结果 | 实施前需处理 |
| --- | --- | --- |
| 系统 | Linux | 发行版/glibc、内存及出站API连通性仍须核对 |
| Python | PATH及常见home/数据盘Conda、pyenv候选路径仅找到3.6.9 | 本项目声明Python≥3.9，现有解释器不满足；建议另装兼容主机的Python3.11/3.12并创建独立虚拟环境，不替换系统Python。此搜索范围不等于全盘没有其他版本 |
| 后端依赖 | 项目要求FastAPI≥0.115、uvicorn≥0.30 | 在独立环境中安装并验证；不能用旧解释器直接启动 |
| Node.js/npm | 10.24.1 / 6.14.12 | 不能按项目当前构建要求使用；按README在本机Node22.12+（推荐24）构建后传递同版本`studio/dist`，远端运行不需要Node |
| 其他运行时 | PATH及常见路径未找到uv、Conda、mamba/micromamba、Podman；Docker客户端24.0.2存在，但当前用户无daemon socket权限 | 不把安装器或容器运行能力当成现成前提；后续选择与主机兼容且经允许的独立运行时方案 |
| 进程管理 | 用户systemd237运行中，`Linger=no` | 用户服务可进一步核验，但退出最后会话后的长期常驻尚未成立，需核对linger等主机策略 |
| 反向代理 | 未发现nginx | 初期SSH隧道无需安装nginx；域名部署另立阶段 |
| 根盘 | 总量约1.8T、剩余约9.8GiB，使用率显示100% | 不在根盘集中放置代码、venv、缓存、书库和备份 |
| 独立数据盘 | 总量约7.3T，剩余约594GiB；已有当前用户拥有且可写的专属目录 | 后续优先使用该用户数据目录，实施前仍核对配额、目录权限、预计用量和备份位置；实际目录仅留私人记录 |
| 目标端口 | 远端TCP8000无监听 | 仅说明核对时可用，实施启动时仍须再次确认 |

以上核对不代表已安装运行时、上传程序、创建服务、开放端口或测试远程生成。

## 3. 推荐第一阶段：回环后端与SSH隧道

```text
本机浏览器 127.0.0.1:18000
        │ 本机回环端口
        ▼
已验证主机密钥的 SSH 加密隧道
        │
        ▼
服务器 127.0.0.1:8000
        │
        ├─ Studio静态前端与API
        └─ 服务器独立工作区、任务、预算与私人资料
```

以下命令是设计示例，尚未执行。实际连接参数从私人记录读取：

```powershell
ssh -N -L 127.0.0.1:18000:127.0.0.1:8000 -p PORT -o StrictHostKeyChecking=yes -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -o ServerAliveCountMax=3 USER@HOST
```

然后在本机打开`http://127.0.0.1:18000/`。服务器保持仅监听回环地址，不开放公网8000/18000端口；18000仅是本机入口。原生浏览器请求仍使用回环Host、同源Origin和现有变更请求令牌，SSH不改写HTTP头。

隧道断开不等于服务器后端或已发送模型请求停止。重新连隧道后先查看原任务状态，不能因网页暂时不可达就重复发起付费任务。SSH隧道的可用性与身份边界依赖服务器账户和本机安全，当前Studio仍不是多用户系统。

## 4. 运行目录与常驻进程

建议在已确认可写的用户数据盘目录下，将代码发行目录、持久化工作区、虚拟环境和备份分开。下列`/DATA_ROOT`为占位，实施时替换为私人记录中核对的真实目录：

```text
/DATA_ROOT/vibenovel/
  app/            # 固定版本代码及与其匹配的studio/dist
  venv/           # 独立现代Python环境
  workspace/      # 小说、私人library、配置、模板及运行账本
  backups/        # 独立完整快照；确认容量后选择存储位置
```

工作区迁移必须包含模板/配置的非敏感部分以及`novels/`、个人`library/`等依赖；不能只复制正文。发行wheel不内置前端，启动须显式指定`--frontend`。前后端应来自同一Git提交和构建清单，避免把新界面配到旧API。

在确认现代Python、安装路径、目录权限、用户服务与容量均满足后，可采用以下用户服务模板；这是待评审的模板，尚未写入服务器：

```ini
[Unit]
Description=VibeNovel Studio
After=network.target

[Service]
Type=simple
WorkingDirectory=/DATA_ROOT/vibenovel/app
ExecStart=/DATA_ROOT/vibenovel/venv/bin/vibenovel-studio --workspace /DATA_ROOT/vibenovel/workspace --frontend /DATA_ROOT/vibenovel/app/studio/dist --port 8000
Environment=PYTHONUNBUFFERED=1
UMask=0077
Restart=on-failure
RestartSec=5

[Install]
WantedBy=default.target
```

模板中的`/DATA_ROOT`不能原样执行，应替换为已核对的用户数据盘绝对路径。venv、模型和包缓存也优先置于该数据盘，避免安装时仍填满根盘。

已发现的用户数据目录为0755；后续应用的私人工作区与凭据子目录应按用途收紧权限，不能仅凭“用户拥有且可写”就认定其他同机用户无法读取。此轮未创建目录或修改权限。

用户管理器本轮已核对运行，但`Linger=no`；若希望退出SSH或重启后继续运行，还须处理主机允许的linger等策略。若当前账户不支持，先选择管理员认可的常驻方式，不假定存在root权限或更改系统服务。单工作区仅启一个后端进程；不使用多worker或多台可写实例共享同一文件工作区。

进程重启策略只负责恢复HTTP服务，不授权重放生成或清零账本。旧任务有未知结果时继续保留原预留与响应记录。日志只记录必要诊断，排查与分享前去除小说正文和配置凭据。

## 5. 迁移、备份和回退

| 数据 | 迁移与备份要求 |
| --- | --- |
| 小说 | 完整`novels/<ID>/`，包括草稿、正式稿、记忆、历史、提案、导入原件和`.runtime/` |
| 付费任务与预算 | 原任务、路由/预算账本、`provider-responses/`及旧任务备份；未知结果和402未结算预留保持，不因换服务器而归零 |
| 私人资料中心 | 全部`library/`与作品`library/`：原书、解析旧新版、直接父子映射、研究批次/检查点、方法来源、独立研究账户及journal |
| 语义模型与索引 | 记录模型版本、源版本及重建条件；索引可重建，不可代替原件或已付费研究结果。BGE运行时还需在目标Linux单独验证 |
| 模型密钥 | 不随Git、前端dist或公共备份上传；如决定远端使用API，单独在目标环境由作者配置并限制读取权限 |
| GitHub认证 | 不是运行Studio的前提；不随部署传输本机GitHub令牌 |

迁移前暂停新任务并核对所有在途请求，停写后制作完整一致快照和文件hash清单。若有SQLite账本，使用一致备份方式或在服务停止后复制，不能复制写入中的单一主文件而忽略journal/WAL。

先以不含私人书籍和密钥的隔离样例验证新环境：启动、静态资源、保存/重读、审批、导出、重启后的任务不重放。之后按作者明确选择迁移真实工作区；API连通性测试另行预览并记费。切换期间保留单一可写主副本，本机旧库先转只读，不能让两边各自写作后再直接覆盖合并。

回退使用成对的代码/前端版本和迁移前完整数据快照。已发送请求及其费用证据先另行保留，不能回退旧账本使已花费用消失。备用副本也不自动执行旧任务。

## 6. 域名与HTTPS的后续阶段

当前Alpha的`LocalBoundary`只接受`127.0.0.1`、`localhost`、`::1`；启动器仅监听`127.0.0.1`且不信任代理头。现有令牌用于本地变更请求校验，并非登录认证。将域名直接反代到现有服务不能形成安全的远程身份边界；不要通过伪造回环Host或关闭Origin检查来绕过限制。

作者提供实际域名后，再设计和实现明确的远程模式：

1. 单用户身份认证、受保护的全部读写/API及静态入口；会话有效期、注销与失效机制。私人正文、原响应和模型设置均受同一身份边界保护。
2. 与真实外部Origin一致的CSRF校验、显式Host白名单及可信代理设置；代理认证不替代应用侧来源和权限检查。
3. 有效TLS证书、HTTPS重定向、证书续期和合适的会话Cookie属性；限制请求体、超时和访问日志，避免代理意外重试已发送的付费变更请求。
4. 防火墙只允许所需的SSH与HTTPS入口，后端仍在回环地址；先完成配置审查与隔离验收，再启用实际域名。

本阶段尚无域名、DNS记录或证书配置，也未实现远程登录与会话。推荐先使用本机固定8000，远端就绪后通过SSH隧道访问；域名作为后续独立交付，不阻塞当前写作。

## 7. 实施前验收清单

- 确认目标主机的现代Python、系统兼容性、足够数据卷/备份空间和用户服务常驻条件。
- 同提交代码与本地构建dist在隔离目录启动，仅回环8000监听；真实工作区及验收47328保持独立。
- 通过本机18000隧道验证页面、保存、审批、下载；断线重连及重启不追加模型请求。
- 完整快照和恢复演练保留原件、版本、研究来源与全部费用账本；私有密钥不进入公开产物。
- 固定域名路线只有在身份认证、CSRF、TLS及防火墙边界完成后验收，不将SSH连接成功写成远程部署已完成。
